# 资产拆分边界与装配验收

读取时机：工站拆分、设备/机构分类、耗材提取、重复实例或机构组装成设备。本页是默认拆分边界；用户明确指定的例外记录对象与理由，不把项目例外推广为全库规则。

## 先区分资产边界和运动边界

资产是采购、复用、版本与交付单元；刚体/link 是仿真的运动单元。一个设备资产可以含多个运动刚体、关节和传感器。保留这些内部模型不等于把商业整机拆成多个库资产。碰撞按真实刚体和空间分组，见 [collision-profiles.md](collision-profiles.md)。

| 对象 | 标准分类及停止拆分位置 | 处理规则 |
|---|---|---|
| 单个成品商业设备 | `04_设备`；保持整机资产 | 离心机、旋蒸仪、天平、成品机械臂等保留厂家整机边界。内部转子、门、轴等保留必要运动与操作接口，不再拆成库中机构。可独立操作的耗材照常提取。 |
| 全部耗材/工件与承载器具 | `02_工件与耗材`；按独立物料单位建立定义 | 从设备或总装中提取瓶、可拆盖、板、吸头、滤芯、载架等。相同型号/规格/配置复用一个固定定义，数量由实例表达；固定不可分的复合耗材作为一个物料定义。 |
| 自制/集成自动化装置 | `04_设备`；引用下列子资产形成装配 | 按可复用功能和采购单元拆分，设备保留协调行为，调用机构行为。来源 CAD 的层级不是最终拆分依据。 |
| 完整直线模组 | `03_机构模块` | 轴及其配套安装板、拖链、轴内限位等保留完整功能单元，不继续拆内部丝杠、导轨、滚珠。拖链依据长直段方向和安装端归属所服务的运动轴。 |
| 完整传感器/检测组件 | `01_零部件` | 按完整采购或成套使用单元建资产，不拆壳体、电路和内部光学件。光纤头与放大器成套时保存在同一定义中，可分置的安装 frame 分别表达；装配时实例化。 |
| 末端工具 | `03_机构模块`，纯静态工具可为 `01_零部件` | 完整夹爪、旋盖头、吸取头等保留安装/TCP/夹持接口和自身行为。夹瓶与旋盖一体或分体的变体按明确设计保留；升降轴独立。 |
| 独立采购的运动部件 | `01_零部件` 或 `03_机构模块` | 对独立用于集成的电机、气缸、电动滑台、旋转执行器和传动单元，停在采购功能单元；可独立动作的完整功能组件作为机构。已经位于封装模组内部的部件不因“可采购”而再次拆包。 |
| 安装板、支架、紧固件 | 随所属功能单元；确需独立复用时为 `01_零部件` | 保留 CAD/BOM 来源与数量；不为每颗螺钉强制建立独立发布资产。 |

“能买到”不等于成品设备：用于搭建自动化装置的电爪、电机、传感器按部件/机构处理；能够作为整机交付并独立完成设备用途的商业产品按设备处理。型号、功能、BOM 或说明书不足时保留待判定，不凭文件名自动下结论。

## 从拆分到组合

1. 清点每个源 occurrence，登记商业整机/自动化装置/耗材/功能单元、目标资产、局部坐标与所有者。沿用已有对象表、BOM 与接口字段，不新建运行时身份体系。
2. 全部耗材独立提取。设备可保留对应库位/装载接口，运行装配用耗材实例填充；移除原总装中的重复物料 mesh，审阅快照与运行入口分别标识。
3. 先检索标准库，再决定复用或新增修订。相同料号还须核对规格、配置、几何、安装 frame 与运动合同；不能仅凭网格相似合并不同产品。
4. 子定义按标准目录封包。自动化设备通过锁定资产引用、实例名、安装 frame 和局部变换组合；需要完整离线闭包时携带校验一致的依赖副本。
5. 机构保存自身轴/关节/限位与行为；设备保存角色绑定和协调行为；项目 graph 保存摆放、实例与端口。无行为的静态部件不生成空动作。设备包消费资产源码/已声明 package，不依赖来源工站仓。
6. 同定义多实例各有独立位姿、轴状态、传感通道、物料 ID 和库位占用。资产保存库位定义，OS 保存当前占用与结算；详见 [asset-library-os.md](asset-library-os.md)。

## 拆分与组装的放行证据

- **完整性**：所有源 occurrence 都能映射到保留几何、独立资产或有理由的排除项；商业整机未被误拆；自动化功能单元未遗漏。
- **耗材与数量**：列出全部耗材类型、定义数和实例数，核对 BOM/实际布置；相同定义没有按数量复制成新资产。48 瓶加可拆盖可为 1 架、48 瓶、48 盖实例，孔位是库位，不是独立载架定义。
- **唯一表示**：组合前后核对源残留和父/子资产引用，确保每个实物在运行视觉、碰撞和库存中各只有一个有效表示，且身份可关联。
- **坐标与运动**：局部/世界变换可往返，安装偏移只应用一次；分别移动直线轴、工具、物料，验证所属对象跟随、其他实例不动，传感方向与安装 frame 一致。商业整机内部必要运动照常验收。
- **原生库**：目录类别/厂家/修订、manifest/BOM、USD 根与引用闭包、行为依赖、碰撞来源通过实际校验；文件复制到新位置仍可读回。
- **OS 组合**：graph、领域包、行为绑定、库位与物料初始化/结算按实际合同验证；未执行的部分写 `not_run`。动画与几何通过分别记录，不代替物理或 OS 结算。
- **第二空项目**：从固定资产重新组装，改名/布局/数量，不改核心行为。核对源摘要、独立状态、位姿和本次要求的动作；让消费者的 Python 搜索路径中不含作者工站仓。

这些判定需要来源与实际场景证据。通用转换器不会从几何自动推断采购边界；通用文件校验通过也不能代替上述语义与运动验收。工具入口及运行时条件见 [portable-tools.md](portable-tools.md)。
