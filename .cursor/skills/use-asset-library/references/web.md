# 设备广场

用户入口是 8766 的 `/` 或 `/types.html`。8765 保留模型准备与插入 API，首页跳转到统一广场；自定义端口配置中的 `square_port` 必须与网页服务一致。

## 浏览和选择

顶部按设备、零部件、模组、耗材与资源、工站、工具、全部资产和专题切换。设备使用学科／场景／阶段全景图；其余类型直接进入多层分类目录，提供分类树、下级文件夹、面包屑和资产卡片，不显示场景矩阵或学科／阶段筛选。厂家、模型、模块及搜索条件继续可用，分类仅显示当前条件下有资产的节点。

分类轴的候选项保留其他轴条件，忽略本轴选择；大类和具体分类属于同一分类轴。`summary.types` 是当前结果计数，`summary.filter_options.types` 才是切换候选及其计数，不能混用。其他轴同理；场景候选仍要求其他场景轴条件落在同一绑定上。目录分别展示全部、已分类和待补分类数。顶部“首次使用 / OSS 权限”链接到 `/setup.html`，引导没有权限的人联系维护者并运行诊断。

专题从当前公共条目的场景关联及当前工程记录的 owner 项目归属生成，点击进入同一套分类目录。它不读取历史集合目录、不创建新包、不改变资产身份。专题条件与设备场景筛选分开；切换非设备类型清除 domain/scene/stage，避免残留条件隐藏资产。分类缺失的条目保留在全部结果中并标明待补分类。

场景矩阵按真实场景—阶段绑定聚合；单个资产分别出现过两个场景，不代表任意场景和阶段都可组合。`has_os_module=true` 仅表示非空模块入口，不是驱动可用性证明。

打开详情核对厂家、型号、参数、资格和关联关系，再取得固定工程引用。有些公共条目只有资料，没有工程包，因此不会出现可插入模型。网页不执行硬件动作。

## 精确接口

服务地址由部署配置决定，下列均为 GET：

| 路径 | 用途 |
|---|---|
| `/api/health` | 服务身份、镜像根、工程索引摘要 |
| `/api/portal/entries?scene=...&has_3d_model=true&page=1&page_size=24` | 分页检索；中文参数用 URL 编码 |
| `/api/portal/summary` 加相同筛选参数 | 当前条件的统计与分类选项 |
| `/api/portal/entries?square=all&resource_type=mechanism` | 模组入口；component/resource/workcell/tool 对应其他类型 |
| `/api/portal/summary?square=all` 的 `topics` | 仅引用当前资产的专题索引；检索使用 `topic=<name>` |
| `/api/catalog/entry?id=<UUID>` | 公共条目详情 |
| `/api/catalog/reference?id=<UUID>` | 当前固定模型引用；无模型时处理缺口 |
| `/api/portal/blender` | Blender 使用的统一目录投影和分类 |

不要把一次网页分页结果当成全库计数。检索有模型的结果后，抽查其引用确实可由桥接服务准备；资格仍以对应包的验收记录为准。
