# 既有资产 CAD 与机构装配标准

读取时机：给已有条目补 CAD；从零部件／机构资产组合设备；生成 SolidWorks 总装、验证原生配合或处理其文件引用。仅做外观编辑时不强制执行完整原生 CAD 流程。

先按 [拆分边界](decomposition-boundaries.md) 确定资产粒度；商业整机保持一个设备资产，内部 CAD/关节结构不要求分包。以下机构组合步骤用于自制/集成自动化装置。可用通用脚本见 [portable-tools.md](portable-tools.md)。

## 1. 同一资产条目增加表示

先按身份和来源定位既有条目，核对 asset ID、catalog ID、类别、型号／设计版本及当前入口。CAD、USD、行为是同一工程定义的不同内容。补 CAD 保持这些身份，更新该条目的 CAD 入口、对象映射、来源、BOM 和索引目标；不要另建“某资产 CAD 版”与原条目并列。

发布按实际库的修订合同执行：目录中一个资产只显示一个条目，旧项目仍可按固定版本解析。内部修订记录与新增资产区分报告。用户另行指定目录更新方式时按其要求处理所有受影响的摘要与引用。完成标准是本轮每个原资产 ID 都有一个可用 CAD 入口、目录索引无同物重复条目，而不是另交一个独立 CAD 文件夹。

为每项列出 `native_file`、`asset_assembly` 或具体缺项。已有原生 CAD 优先保留；只有交换格式时由真实 CAD 内核导入并验证实体。自定义件从已有参数化模型或设计尺寸恢复实体，标明设计重建与假设。原生 B-Rep、原始特征历史和制造资格分别记录。源实体与网格按定义、实例和坐标映射；包围盒相等不能单独证明孔槽和实体正确。没有来源的形状不能标成厂家 CAD，三角网格改后缀不能算补齐。

## 2. CAD 所有权与目录

| 对象 | 当前资产保存 | 通过引用复用 |
|---|---|---|
| 成品商业设备 | 厂家整机 CAD/依赖闭包、内部运动和操作接口 | 整机实例；耗材独立引用 |
| 独立零部件／耗材 | `.SLDPRT`，或按实际结构保存 `.SLDASM`；对应 USD 和 CAD 映射 | 相同件的多个 occurrence |
| 自有零件组成的机构 | 自有 CAD 定义、原生装配与关节声明、机构行为 | 已入库的采购件／子机构 |
| 已入库机构组成的设备 | 固定装配引用、自有安装件 CAD、设备协调行为 | 子机构 CAD、几何、接口与行为 |

父资产由其他已入库资产组装时，保存引用即可，不要求在父条目重复保存子资产的完整 CAD 或生成的总装。它自己新增的安装板等仍由本条目持有，或在确有独立复用价值时进入独立条目。重复摆放使用同一定义的多个实例；建立新方案与给原资产补文件是不同操作。

沿用现有原生包与元数据扩展，不为 CAD 新建另一套资产库：

```text
<分类>/<厂家>/<既有资产修订>/
├─ com.nvidia.simready.packaging.json
├─ .metadata/                         # 原生 BOM、根 USD 声明
└─ simready_usd/
   ├─ <资产修订>.usdc
   ├─ unilab.json                     # CAD/空间入口、行为、接口、依赖
   ├─ readiness.json
   ├─ behavior/…                     # 有专属行为时
   └─ cad/
      ├─ assembly.json               # CAD 映射、实例与固定资产引用
      ├─ native/*.SLDPRT|*.SLDASM     # 本条目拥有的定义；按需要存在
      └─ source/…                    # 实际保留的实体来源

<项目缓存>/solidworks/
├─ <设备>.SLDASM                      # 按引用按需生成
├─ parts/…
├─ groups/…
└─ <构建与运动检查回执>
```

采用已有 `cad_binding`／`entrypoints` 合同；当前 UniLab 的资产 CAD 入口为 `entrypoints.cad`，目录用途为 `engineering`。本条目的 native 路径为包内相对路径；子资产记录 asset ID、包路径和摘要。外部 CAD 定义走通用依赖，不伪装为 OS 行为角色。CAD 来源路径只作追溯，不能成为消费时隐含依赖。实际 SolidWorks 文件引用也要验证，不能只检查 JSON 路径。

## 3. 机构组装到设备

装配配方保存实例 ID、角色、所用资产与配置、父实例、源／目标 prim、安装 frame 和局部变换。声明单位、轴向、零位及矩阵乘法约定；CAD 原始摆放到资产局部的变换只去除一次。用非零平移、旋转与复制实例核对组合结果。

机构拥有自身轴线、行程依据、移动刚体、安装输出和行为；设备通过注入的机构接口协调过程。模型显示层次、实际机械安装层次、OS 逻辑别名可能不同，组装器要显式映射。例如工具在 USD 根部平级放置，但机械上装于 Z 滑台时，必须建立该随动关系。设备的运动检查应观察工具／传感器等下游部件实际跟随，而不是只看导轨动了。

同一部件可供不同方案和旧设备共用，但要核对型号、配置、几何、安装基准及运动接口。组合式与拆分式方案选择一种实例结构，避免同时摆入两份实体。光束、刻线和坐标轴等非实体注记明确分类；完整传感器的 CAD 与射线行为分别保存和验证。

## 4. SolidWorks 原生装配与配合

保持可运动的刚体分组。组内固定，组间按声明建立原生配合；只给所有实体写初始 Transform 或将整个机构固定，不等于具有关节能力。

- 固定安装：使用刚性安装关系，保留正确的相对位姿。
- 移动副：导向／防转与轴向自由度分开；可用距离配合驱动位置。测试范围、尺寸驱动和原生硬限位分别说明。
- 转动副：轴线与轴向定位保持一致，保留需要的旋转自由度；角度驱动按任务接入。
- 同步带、齿轮、丝杆、离合：只有传动关系有依据且实际实现时才声明联动。OS 规定轨迹不自动成为机械耦合或受力证明。

轴向应由安装变换映射到最终装配坐标。负轴同步处理符号；斜轴使用显式局部关节 frame。复合轨迹无法直接映射到一种配合时记录未支持项，不能静默固定后声称完整运动通过。辅助关节坐标件从实体 BOM 排除。

优先保留已有有效配合；重建时逐组核对预期自由度、初始位姿和实际求解结果。供应商实体导入生成的 CAD 不自动恢复其参数化特征历史。

## 5. 文件引用、性能与恢复

原生子装配和辅助件使用资产内可辨识、跨资产不冲突的文件名；多个目录里的 `base.SLDASM` 等同名文件可能被 SolidWorks 错误复用。批量插入可复用现有 API，但插入后读回实际文件路径和矩阵，检查名称冲突及实例丢失。

大装配先测代表性机构，再批量生成。可采用批量插入、隐藏生成过程的文档视图、分刚体组关闭文档和按实体摘要／配置缓存，记录生成、打开、求解的实际耗时。缓存复用须核对来源摘要、配置和装配变换；不要只因文件存在就跳过。SolidWorks 不同接口的“暂停重建”含义需在当前版本验证，不能据名称假定所有求解已暂停。

长任务按组持久化进度、已保存文件与错误。工具超时与 CAD 进程完成分开判断，避免重复启动。无进展时先检查应用状态；恢复只处理本任务拥有的进程和文档，保存失败证据、复用已校验结果。一次 API 阻塞的恢复办法不作为所有环境的强制操作。

## 6. 分层验收

1. **覆盖与身份**：逐项确认原资产 ID、唯一目录条目、CAD 入口、所有实体／引用／非实体注记的去向。补 CAD 未改动的 USD、行为与接口按摘要核对。
2. **封包与冷消费**：原生封包、CAD 与 USD 的依赖闭包、固定子资产版本和索引一致；从服务器空缓存解析，消费过程不依赖作者仓。
3. **原生重开**：源工作目录不可用时，在另一目录实际打开 CAD；检查警告、配置、实体数量、实例位姿与真实引用路径。保持原资料，只对本任务可恢复的副本做隔离测试。
4. **整机装配**：从资产引用生成完整设备，核对部件覆盖、重复实例数量、关键安装基准与 CAD／USD 世界位姿；保存整机可重开的闭包到项目输出。
5. **关节运动**：移动副在声明范围内取起点／中点／终点，转动副测试多个角度；读回实际位姿、求解状态和子件跟随，并恢复初态。复制实例分别运动，检查另一个实例是否被误带动。抽查须列出覆盖，不称为全部关节通过。

文件可开、静态装配正确、原生配合可动、OS 行为执行、碰撞／间隙、接触受力、制造与实机资格分别结论。CAD 运动不能替代其余能力验收；SolidWorks 大装配成功也不等于 Blender／Isaac 的运行已重新验证。

当前 Asset_pipeline 可复用 `cad_composition.py`、`solidworks_assembly.py`、`native_package.py`、`native_transfer.py` 及相应审计工具；先在实际仓中检查接口。这些工具不随本技能捆绑，也不是消费资产必须取得作者项目的理由。
