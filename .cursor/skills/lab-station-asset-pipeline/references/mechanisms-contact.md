# 机构、接触与任务验证

读取时机：需要门、抽屉、机器人、夹爪运动，或资产将参与落稳、抓放、插入等接触任务时。
从当前任务的作用区和成功条件选择模型，不把整站所有零件都设成自由刚体。

## 机构证据与建模

1. 为每个可动机构列出父体、子体、关节类型、轴、原点、零位与范围。
2. 优先采用匹配版本的原生配合、厂家 URDF、图纸或实际测量。
3. 仅凭形状推测的轴与范围标为候选；静态 STEP 的摆放不等于关节定义。
4. 区分显示动画、运动学驱动和动力学驱动，记录当前实现支持哪一种。
5. 固定螺丝可并入父刚体；门、滑台、夹指和执行对象按实际作用关系建模。
6. 质量、惯量和摩擦注明数据源；工程假设可用于开发，但应在结果中可追溯。

机构定义与过程效果分别建立，例如抽屉打开不自动意味着制冷、离心或液体转移发生。

## 厂家模型与现场几何对齐

- 为 URDF link 和 CAD 总成建立显式对应；记录型号、版本和附件差异。
- 分别检查 base、各关节、flange、工具安装面、tcp 和传感器 frame。
- 工具法兰、夹爪安装块和传感器不要因为外观接近就认定已经正确安装。
- 对齐依据应包含实际几何或安装特征；旋转后的局部 bbox 不能给出精确端面位置。
- 补充法兰、夹指或光轴时，记录推导尺寸和仍需测量的量。
- 没有厂家驱动接口不影响运动模型开发，但不能声称硬件驱动已经贯通。

## 多姿态核验

选零位、典型工作位和接近使用范围边界的姿态；姿态数量与机构复杂度相称。
核对父子连接、轴方向、角度符号、限位和末端几何是否共同随动。
对夹爪同时检查开闭行程、双指联动、抓取中心和指尖作用面。
对门与抽屉检查铰轴/导轨、极限姿态和相邻固定几何的干涉。
保存可重现的配置与渲染，必要时测量关键 frame 距离和姿态误差。
只通过零位外观匹配时，运动资格保持未验证。

碰撞表示的归组、规划外包、来源锁定与运行时消费见 [collision-profiles.md](collision-profiles.md)；本页维护机构和物理接触验证。

## 按任务选择碰撞模型

| 对象或任务 | 可选模型 | 关键核验 |
| --- | --- | --- |
| 远离操作区的固定结构 | 简单碰撞或静态三角网格 | 支撑面和通道不能错位 |
| 外形近似凸的刚体 | 基本体、凸包或少量凸分块 | 接触区与尺寸误差 |
| 有孔板、瓶口、槽、夹持凹部 | 保留空腔的分块或可用引擎支持的 SDF | 孔是否被填、薄壁是否失真 |
| 只需视觉展示的内部细节 | 视觉几何，不添加碰撞 | 仍保留源身份与外观 |

不默认使用 SDF，也不默认把复杂资产压成一个凸包。
先说明本次必须保留的孔、槽、边缘和抓取带，再选择可接受的复杂度。
质量与惯量的来源可以不同于碰撞简化来源，避免把空心容器当作同外形实心块估算。
碰撞层与视觉层分开，给误差预算和模型选择理由。

## 空腔与碰撞检查

板与适配器的插入任务检查完整插入路径及终点：内侧夹片相对孔壁、转角加强筋、底裙与支撑面，以及各圆底是否进入对应孔。照片中实心夹片不能通过人为开槽消除干涉；先重新核对位置、宽度和朝向。可拆上部结构作为适配器引用时，装配基准采用有依据的固定孔，避免改动底座掩盖配合错误。孔位几何定版与螺纹规格、有效深度、螺钉长度的紧固确认分别记录。

1. 比较源表面与候选边界，检查对操作区有影响的偏差。
2. 空腔任务增加源自由空间探针，检查候选是否把自由空间填成实体。
3. 闭合源可以做包含关系检查；源不闭合或没有有效探针时明确记为未完成。
4. 不把“边界距离很小”单独作为孔槽可用的证据。
5. SDF 记录表面准备、分辨率、组件拆分和实际 cooking 结果。
6. 作者写出的 SDF 属性与引擎实际使用的碰撞表示分开核验。
7. 警告按具体对象、组件与日志归因，先用最小对象定位再调整配置。

对于多个闭合组件，分别烹制可能比单个复杂整体更可靠，但应以当前引擎结果决定。
需要修正 winding、焊接或去退化面时记录阈值与改变量，保留孔槽并复查闭合性。
验证器新增空腔判断时，可用一个保孔正例和一个填孔负例验证关键行为。

## 从单物件推进到工站任务

按依赖逐级验证：单物件静态 → 单物件落稳 → 小型接触工台 → 目标工站配置。
工台记录物件来自哪个源实例、如何重定位、支撑面和初始间隙。
原始摆放通常没有为全部物件同时成为自由体设计；先选真实参与动作的对象。
若只修改展示层或非作用区材质，不需要为此重复整套动力学任务。
发现新接触失败时，再扩大相关验证范围。

## 落稳与抓放检查

开始前检查初始穿透、支撑、尺度、刚体状态、约束和碰撞是否实际启用。
落稳读取物件姿态、线速度、角速度及接触，观察时长与物体尺度相称。
抓放覆盖靠近、闭合、提起、运输、放下、释放、撤离和最终稳定。
判断成功时使用物件实际位姿和接触结果，而不是仅使用命令轨迹或完成回执。
双指夹持关注双侧有效接触、持续抬升、携带距离、释放后的脱离与最终支撑。
释放后继续撤离夹爪并观察，防止把残余夹持或约束误判成稳定放置。
若声称接触自然产生了携带，确认 rollout 中没有对象位姿回写或隐藏绑定。
若任务本来采用吸附、磁吸或显式抓取约束，记录该机制并验证其启用与解除。
需要区分夹持与脚本附着时，可增加张开夹爪等针对性对照。
需要重复性结论时使用多次独立运行，明确初值变化和样本数，不设通用固定次数。

通用运动夹指验证的是该夹具与物件的接触任务；它不自动证明现场夹爪、机械臂或控制链可用。

## 证据与能力分项

记录资产哈希、任务配置、引擎版本、步长、执行脚本、输入参数和原始观测。
区分 authored 属性、引擎加载成功、原生步进和任务成功四类事实。
按资产或任务分别标注外观、几何、运动、机械接触、工艺效果、观测、交付能力。
每项写已验证、未验证或不适用，并附范围；具体失败单独记录原因和证据。
同一物件在工台通过的接触证据可复用，但换模型、碰撞表示或关键条件后需复核相关项。
仿真缺少运行环境时交付模型、静态检查和待执行配置，不将其标记为已运行。
