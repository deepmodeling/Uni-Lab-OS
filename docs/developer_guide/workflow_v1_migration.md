## 2026-11-11 持久资源声明与未知派发阶段

调度器继续使用 dev 的资源授予策略，但动作下发前必须把完整资源申请、稳定 Claim 身份和
每个锁键的递增令牌写入 runtime.db。Claim、租约和令牌在同一 SQLite 事务内取得；
相同尝试重放不得改变资源集合，旧令牌、损坏租约和已结束尝试不能再次取得执行资格。

初始化调度器先恢复全部未释放声明，再启动任何任务。因此恢复任务的顺序不会让新任务
抢走旧尝试仍在使用的设备或物料。派发调用抛异常不能证明设备没有执行：该尝试进入
execution_unknown，保留资源等待真实回执或人工核实。停止调度进程不再等同于取消实验。
已落终态但未放锁的崩溃窗口由下次恢复收敛；未知状态不会按超时自动释放。

runtime.db 新增 v5 迁移，保留 v4 已有工作流及修订并生成迁移前备份。旧版本在飞尝试
没有持久资源声明时，调度器以 legacy_execution_reconciliation 原因关闭新派发；
全部遗留尝试核实后恢复。人工确认节点和纯控制流节点不进入这个设备执行闸门。

## 2026-11-11 恢复前置核实与资源区间规则阶段

修复恢复时的释放漏洞：此前重建计划或库存预留失败会走通用 DAG 清理，可能把尚未
核实的旧动作改为 canceled。现在先用已持久化的 Claim / attempt 接管全部旧动作，
等真实迟到结果或人工核实全部完成，再解释工作流图并预留后续库存。核实不依赖
新版本仍能理解旧图或读取驱动注册表；取消中的任务也必须等所有旧动作收敛。

close_node_run 不再允许把在飞、取消请求中或待核实的设备动作直接改成终态；
finish_task 同样拒绝在旧动作未收敛时结束任务。只有确定没有调用执行器的派发前
失败才直接记录失败。恢复后完成的工作流仍走声明输出求值和校验。

新增持久库故障测试覆盖计划失效、取消后重启、多动作逐个核实，以及清理入口拒绝
覆盖未知事实。HostLink 虚拟驱动测试中，第一步实际执行后延迟返回，重启调度权威，
新权威保留占用并接收旧结果，再执行第二步；设备调用恰为两次，最终声明输出正确。
这项证据是本地 HostLink 故障测试，尚不是多机 slave 或真实硬件验收。

从 v1.0 迁入 scheduler/resource_plan.py 与 resource_keys.py 的无副作用规划规则：
连续资源区间、完整原子取得集合、嵌套资源作用域、绑定后别名合并、跨流程静态死锁
检查，以及 pick/place 持料区间约束。34 项原有纯规划合同测试迁到 dev 后通过。
旧架构的集成用例尚未移接，不计入本阶段通过数。

这些规划规则尚未接入 dev 任务派发和持久资源占用，不能据此声称已实现跨步骤保锁、
空闲借还或设备托管。下一阶段需要把冻结区间映射到 dev 的任务/节点运行/attempt，
实现区间所有权与单步执行权分离，再接物理释放和库存结算。D1 跨库恢复、R1 运行时、
I1/S1/C1/F1 与 E1 仍未完成；不缩小完整迁移目标。


## 2026-11-11 持久资源区间运行阶段

本节更新上一个阶段“尚未接入运行时”的状态。调度计划现在按循环层级冻结设备资源
区间；设备身份沿用 dev 的可读 ID。runtime.db v7 新增区间所有权、单次动作准入和
实际使用清单，保持 dev 原有逐动作 Claim / Fence 与授锁策略。

同一设备的连续步骤可以共享一个区间。前一步完成、后一步尚未开始，以及用户暂停
或调度权威重启时，区间仍保留；动作的实际使用权独立释放。并行分支共享显式作用域
时，对同一设备的真实调用仍串行。每次循环使用父循环 attempt 与轮次组成的代次，
不能拿新一轮的终态替旧一轮解锁。

完整资源集合原子取得：冲突和 SQLite 写入失败不会留下部分新增占用。开始许可会
核对动作准入、冻结区间集合和实际使用清单。旧 v6 在飞 Claim 没有区间准入时关闭
新派发，核实旧动作后才重新开放；v6 升级保留旧流程并生成升级前备份。

显式作用域发生失败、取消或执行未知时保留为 retained。即使重试已经把节点当前
attempt 改成 pending，也要检查旧准入历史，不能掩盖前次失败。迟到结果可以收敛动作，
但不会自动替显式作用域做物理清场确认。尚有在飞或待执行步骤时不能手工释放；
应先取消该作用域剩余步骤、核实动作结果，再填写物理状态说明并按版本确认释放。
本阶段尚未实现显式异常区间原地恢复/借还，不能把人工释放当作“继续重试”。

新增接口：

- PUT /api/v1/workflows/{workflow_uuid}/resource-scopes：
  revision + scopes 完整替换。scope 包含 scope_id、kind（root/with/action）、
  resources（当前实例设备 ID）、node_uuids，可选 parent_scope_id。
  通过专用接口写入保留元数据；普通 metadata 更新不会修改它。
- GET /api/v1/workflow-resource-intervals?task_uuid=...：
  查看活动区间、资源键、成员节点、代次、状态和版本。
- POST /api/v1/workflow-resource-intervals/{owner_uuid}/release：
  expected_version + reason。说明必填，陈旧版本、正常 held 区间及未收敛动作均拒绝。
  释放提交后唤醒其他等待任务，重复提交返回已记录的释放结果。

显式作用域目前要求明确列出同一循环层级内的成员；跨循环边界明确报错。
