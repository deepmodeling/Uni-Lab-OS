# AGENTS.md

This file provides guidance for coding agents working in this repository.

## Build & Development

```bash
# Default installation needs only Python 3.14; ROS 2 is explicitly optional
python scripts/dev_install.py  # uv by default (pip fallback): active venv/Conda env, else ./.venv on CPython 3.14; builds companion PLR / Opentrons wheels, no PyPI upload
python scripts/dev_install.py --extras full  # docs, tests, driver SDKs and development tools

# Run with a device graph
unilab --graph <graph.json> --config <config.py>  # HostLink, no ROS runtime or messages
unilab --graph <graph.json> --config <config.py> --backend ros2  # requires unilabos-ros2

# Common CLI flags
unilab --test_mode                        # simulate hardware, no real execution
unilab --check_mode                       # CI validation of registry imports
unilab --skip_env_check                   # skip auto-install of dependencies
unilab --visual rviz|web|disable          # visualization mode
unilab --is_slave                         # run as slave node
unilab --root_devices_as_slaves           # Host runs each root device (with its subtree) in its own managed Slave process
unilab --role backend                     # scheduler authority and runtime.v1 control plane, without devices or ROS (--port, default 8002)

# Workflow upload subcommand
unilab workflow upload -f <workflow.json> -n <name> --tags tag1 tag2

# Tests
pytest tests/                              # all tests
pytest tests/resources/test_resourcetreeset_groups.py  # single test file
pytest tests/resources/test_resourcetreeset_groups.py::test_name  # single test
```

## Architecture

### Startup Flow

`unilab` CLI → `unilabos/app/cli/parser.py:build_parser()` → `app/cli/router.py` handles lightweight subcommands (`package` included) → `unilabos/app/main.py:main()` loads config and starts device runtime only when no CLI subcommand handled the request. Default `unilab` is a two-process tree (`app/backend_main.py`, `app/supervisor.py`): the `unilab` process itself is the scheduling authority (Scheduler / Workflow / Registry / Materials, owns the `--port` management API the browser connects to) and directly supervises the Host child (devices, HostLink, telemetry, driver packages; started with `--address` pointing back at the authority, databases under `<root>/edge`). The Host child binds no HTTP port: it only makes outbound HTTP calls (materials / registry / workflow reports, response delivery) and keeps the runtime.v1 control WebSocket. Host-only routes are served by `server/api/edge_proxy.py` sending a `backend_http` notice over that WebSocket; the Host runs the request against its own ASGI app in-process and posts the result to `POST /api/v1/edge/http-responses/{request_uuid}`. Payload pulls, restart notification and the device relay use the same channel, so the browser sees one address. `POST /api/v1/restart` defaults to `scope=edge`: only the Host child exits (code 75) and is relaunched; the authority and its port stay up, and it rejects `scope=process` for itself. `--role backend` runs the authority alone, on the same `--port` / `BasicConfig.port` setting as the default authority (8002; an old `HTTPConfig.backend_port` is ignored with one startup warning); `--address` runs a top-level Host against a remote authority (only then a thin supervisor from `app/supervisor.py` wraps it for whole-process restarts; unlike the Host child it serves its own `--port`, so next to a `--role backend` on one machine it needs a different port); `--no-safe-restart` collapses everything into one process (debugging); `--is_slave` and `--check_mode` never get any wrapper. Children follow their local parent (`app/lifetime.py`): the spawner writes `UNILABOS_PARENT_PID` (`follow_parent_env`; consumed and removed by `app/main.py:main()` via `follow_parent_from_env`), the follower polls `getppid()` (POSIX) or waits on the parent's process handle (Windows), the Host child and the thin supervisor's inner process (spawned from a long-lived thread) also get `PR_SET_PDEATHSIG` on Linux, and on Windows the spawner puts them in a KILL_ON_JOB_CLOSE job; managed Slaves (`server/services/device_processes.py`) follow their Host by polling plus the Host's job (no PDEATHSIG: it tracks the spawning thread, and Slaves are started from API / timer threads). A managed Slave is treated like one on another machine: whatever it needs from the Host or other devices comes over HostLink / DDS / HTTP, never from the Host's process (`slave_environment` restores the ROS networking variables the Host set for its own nodes, e.g. `ROS_SUPER_CLIENT`; ROS 2 Slaves run Fast DDS over UDPv4 only through a generated `FASTRTPS_DEFAULT_PROFILES_FILE`, unless the user set Fast DDS transports or the Host's loopback drops IP fragments, as under WSL2 mirrored networking, where they keep the Fast DDS defaults), and drivers of different root devices interact only through the framework. Stopping one sends SIGTERM (Windows: Ctrl+Break to its process group) and kills after `STOP_GRACE_S`. A follower whose parent disappears (SIGKILL, crash) runs its own SIGTERM path, bounded by `lifetime.SHUTDOWN_DEADLINE_S`. Only the local parent counts: an `--address` Host follows its thin supervisor, never the remote authority, so a dropped link only reconnects. Shutdown: the authority treats SIGTERM / SIGHUP like Ctrl+C (`backend_main._stop_on_signal`; uvicorn re-raises the signal after its graceful drain, which with the default disposition used to kill the authority before its `finally`), asks the Host to exit at the first signal, fails pending `backend_http` waits, and kills a Host that is still alive after `CHILD_EXIT_GRACE_S` (also one launched while stopping); the Host's handler acts once (repeated signals are ignored) and wakes `wait_routes_ready`; runtime processes leave through `lifetime.exit_now` (atexit callbacks, then `os._exit`) instead of interpreter finalization, which joins every thread-pool worker. One process owns one database root: before opening any database, `app/main.py:_claim_process_database_root` takes an exclusive OS lock on `<root>/unilab.lock` (`server/database/root_lock.py`; the authority holds `<root>`, its Host child `<root>/edge`, `--role backend` `<root>/backend`, each managed Slave its own `device_processes/<id>/database`; `--check_mode` takes none), re-entrant within the process and released by the OS on exit; a second instance exits with code 73. A `hostlink` Host opens its HostLink port right after config load, before the registry, graph and devices (`client/host/hostlink/startup.py:prebind_host_server`, called from `app/main.py`); `HostLinkBackend.start()` adopts that server and gates Slave requests until `materials` (authority attached) and then `devices` (local devices and host services started) are ready, answering "Host 启动中" (`not_ready`) that Slaves retry within `HostLinkConfig.host_wait_timeout`. Runtime then builds the registry, loads the device graph (node-link JSON, registered with the Graph Authority), and starts `hostlink` or `ros2`. HostLink's local driver executor is `unilabos.client.host.hostlink.local_runtime.HostLinkLocalRuntime`.

### Core Layers

**Registry** (`unilabos/registry/`): Singleton `Registry` class discovers and catalogs all device types, resource types, and communication devices from YAML definitions. Device types live in `registry/devices/**/*.yaml`, resources in `registry/resources/`, comms in `registry/device_comms/` (all read recursively; a declared `category` is kept, the file stem is only the fallback). The registry resolves class paths to actual Python classes via `utils/import_manager.py`. Loading is ordered: files merge in sorted path order and entries in declaration order, independent of thread timing and the string hash seed (the first YAML file wins a duplicate id). Unless the backend is `ros2` (for library use and `--check_mode`: unless ROS 2 is installed), the registry build never imports `unilabos.client.host.ros2.*` or `unilabos.devices.ros_dev.*` and does not scan `devices/ros_dev`; the ROS 2 presets (`camera`, `serial`) stay registered so HostLink can mark such graph nodes unavailable (`registry.py:ros2_core_enabled`). Every JSON action (`@action()` without `action_type`, and `auto-` methods) gets one signature-derived schema (`registry/action_schema.py`: the AST scan builds a draft per parameter with the strict annotation parser, unknown annotations fall back to the registry's signature inference in `Registry._infer_annotation_schema`), carrying the `x-unilabos-action-contract` v2 envelope; the scheduler, run preflight and the Host validate arguments and results against it (`registry/typed_contract.py`). Resource semantics are one experimental decorator field, `@action(material_contract=MaterialRole.move(...) | [...])` (`registry/material_roles.py`; the factories live on the frozen `MaterialRole` dataclass they return, named apart from the runtime `unilabos.resources.materials`; any use warns once per definition; the old field name `material=`, the short-lived `materials=` and the old class name `Material` — still importable, but `Material.xxx(...)` fails at import and in the AST scan — are rejected with the new spelling): the material actions are `MaterialRole.move` / `pick` / `place` / `dispense` (sites are `SiteSlot` uuids whose owner the scheduler derives from the site, carriers are `DeviceSlot` parameters defaulting to the executing device and its `gripper` site); `load` / `unload` / `in_place` / `site_picker` / `order_sensitive` are the declarations that are not material actions. A site parameter is annotated `SiteSlot`; `MaterialRole.site_picker(...)` writes the selector hint into that field's `x-unilabos-site-selector` extension. `Material.transfer` / `aliquot` / `site` / `uses` and `pick` / `place` with `owner` / `site` / `carriers` are rejected with the new spelling. Parameters are locked by type: `ResourceSlot` material locks, `DeviceSlot` device locks, `SiteSlot` site locks. Frontend selectors: the entry's `placeholder_keys` is the type-derived set (`ResourceSlot` / `DeviceSlot` / `SiteSlot`) united with `@action(placeholder_keys={...})`, the hand-written kind winning per parameter (`registry/placeholder_keys.py`); it changes only the display. The material lock is a union: `ResourceSlot` parameters plus every parameter whose merged selector is `unilabos_resources`, which is how signature-less YAML and ROS / protocol entries mark their materials. `contract=`, `resource_contract=`, the old `material=` / `materials=`, JSON-action `goal=` / `result=` renames, the removed `Placeholder` / `SiteSelector` annotations and an `action_context` parameter without the `ActionContext` annotation are rejected by both the decorator and the scan (`registry/action_options.py`). The framework injects `ActionContext` by type: any parameter annotated `ActionContext`, `Optional[ActionContext]` or `ActionContext | None` gets it (the optional forms get `None` when there is no context, e.g. under ROS 2), and such parameters are excluded from the schema, handles, `placeholder_keys`, material locks and `goal_default` (`registry/action_context.py`, `client/host/runtime/action.py:bind_action_context`). Rules: `docs/developer_guide/action_standard.md`.

**Resource Tracking** (`unilabos/resources/resource_tracker.py`): Pydantic-based `ResourceDict` → `ResourceDictInstance` → `ResourceTreeSet` hierarchy. `ResourceTreeSet` is the canonical in-memory representation of all devices and resources, used throughout the system, and it owns every resource conversion: flat dicts (`from_raw_dict_list`, `dump`/`load`) and PLR (`from_plr_resources`, `to_plr_resources`). PLR drafts from a registry resource class come from `resources/materials.py:instantiate_registry_resource`. There is no separate graph I/O module: device graphs are node-link JSON only (GraphML is not supported) and are turned into runtime structures by the Graph Authority (`server/services/materials/graph.py:load_graph_payload`).

**Device Drivers**: vendor drivers (PRCXI, LaiYu, Bioyond, HPLC, balances, arms, …) are not in this repository. They live in external driver packages, installed with `unilab package install` (`app/cli/package.py`, `server/services/driver_packages.py`) or mounted with `--devices`; create new ones with `.cursor/skills/create-device-package`. A driver is a Python class with `@device` / `@action` decorators that the runtime wraps as a HostLink or ROS 2 device node. Driver packages that define PLR resource or backend classes outside their registry entries register them with `register_plr_module()` / `@register_plr_class` from `resources/plr_additional_res_reg.py`, so `ResourceTreeSet.to_plr_resources()` can deserialize them. `unilabos/devices/` keeps only the built-ins the framework depends on: `workstation/workstation_base.py` (`WorkstationBase`, `WorkStationContainer`), `virtual/*` (used by the protocol compilers, `--test_mode`, example graphs and tests), `liquid_handling/liquid_handler_abstract.py` with `rviz_backend.py`, and `ros_dev/liquid_handler_joint_publisher*.py`.

**Device Runtime** (`unilabos/client/host/runtime/`): Transport-neutral device execution kernel shared by HostLink and ROS 2 — `DeviceNode`, action routing, resource service, and runtime exceptions (`DeviceActionError`, `DeviceClassInvalid`, `ActionResultError`).

**Transport Layers**: `unilabos/client/host/ros2/` wraps device classes as `ROS2DeviceNode` instances; its presets include `host_node`, `workstation`, controller, serial, and camera nodes. `unilabos/client/host/hostlink/` provides the HostLink transport runtime plus its own `host_node.py:HostNode` and `workstation.py:WorkstationNode` (the ROS2 counterpart keeps its original name `ROS2WorkstationNode`); `unilabos/client/host/dora/` is experimental. The package `__init__` of `unilabos/client/host/` is the public transport catalog shared by the CLI and runtime (`BackendProfile`, `resolve_backend_selection`, `start_backend`). The per-backend host/workstation orchestrators share transport-neutral logic from `client/host/runtime/` (`host_adapter.py:HostAdapterBase` for bookkeeping/bridge notification/ping-pong/test-mode, `workstation_protocol.py` for protocol name/model resolution and resource expand/write-back) and carry no `@device` decorator. `client/host/host_services.py:HostServices` uniquely defines the host service actions; the file is excluded from the default registry AST scan and scanned separately by `Registry._setup_host_node`. Host-to-device material and management requests use the module-level functions in `client/host/hostlink/downlink.py` (cross-machine channel is HostLink RPC; ros2 reuses it).

**Experiment Protocols** (`unilabos/experiments/`): `models.py` holds Pydantic parameter models for XDL-style experiment actions (mirroring `unilabos_msgs` ROS actions); `compile/` holds 20+ protocol compilers (add, centrifuge, dissolve, filter, heatchill, stir, pump, etc.) that expand protocol steps into device action sequences at execution time (consumed by the `workstation` preset node). One-shot workflow import converters (`from_xdl.py`, `from_python_script.py`, legacy JSON) live in `scripts/workflow/`, not in the runtime packages.

**Communication** (`unilabos/device_comms/`): Hardware communication adapters that external driver packages build on — OPC-UA client, Modbus PLC, RPC, and a universal driver. `app/communication.py` provides a factory pattern for WebSocket client connections to the cloud.

**Scheduling and Execution**: the authority side is in `unilabos/server/`: `scheduler/` (`BackendScheduler`: DAG runner, action/material locks, inventory admission), `edge_dispatch.py` (the runtime.v1 control plane that dispatches to the Host) and `lifecycle/` (shutdown signals in the package `__init__`, plus `drain.py`, `restart.py`, `reset.py`). The Host side is in `unilabos/client/host/`: `execution.py` (job execution backend), `edge_executor.py` (persistent coordinator of Backend commands), `execution_start.py`, `capabilities.py`, `incidents.py`, `telemetry.py`, and `legacy_adaptor/` (the Host's link to the Backend). `server/execution_composition.py` wires both on top of the four-database `server/composition.py`; it, `execution_queue.py` and `inventory.py` are still used by both processes. Apart from `host/`, `unilabos/client/` holds the clients that call the server. There is no `unilabos/backend/` or `unilabos/server/backend/` package any more.

**Microbackend HTTP API** (`unilabos/server/api/`): FastAPI routers and the Host management application. It exposes runtime, materials, telemetry, history, and scheduler observation APIs on port 8002 by default.

### Configuration System

- **Config classes** in `unilabos/config/config.py`: `BasicConfig`, `WSConfig`, `HTTPConfig`, `ROSConfig` — all class-level attributes, loaded from Python config files
- Config files are `.py` files with matching class names (see `config/example_config.py`)
- Environment variables override with prefix `UNILABOS_` (e.g., `UNILABOS_BASICCONFIG_PORT=9000`)
- Device topology defined in graph files (node-link JSON; GraphML is rejected)

### Key Data Flow

1. `-g <file>.json` → old-format graphs (legacy cloud exports, dev-era examples with `class`/root `position`/`children`) are upgraded once at the `-g` / `unilab graph upload` read boundary by `client/host/legacy_adaptor/legacy/graph.py` (material nodes without a PLR class get `template_name` / `class` / `config.type` from the registry entry of their template — the Host's local scan for `-g`, the target authority's `/api/v1/registry/entries` for upload — and an unknown template is an error naming the node) → the Graph Authority (`GraphService.upsert_graph`, `on_existing="adopt"`) assigns identities and stores the snapshot → `app/main.py:_load_startup_graph` feeds the authority payload to `load_graph_payload()`, which returns `LoadedGraph(resource_tree_set, links, physical_setup_graph)`. `-g <name|uuid>` skips the file step and loads the stored snapshot. The Graph Authority accepts the current node-link contract only. `physical_setup_graph` (`nx.Graph`, edges carry `port`) is only for the protocol compilers and is published through `client/host/runtime/workstation_protocol.py:physical_setup_graph()`. A Slave holds only its own graph (a managed Slave: one root device's subtree), so it fetches the Host's full graph over HostLink (`graph.physical.get`; HELLO / PING carry `physical_graph_revision`; `client/host/hostlink/physical_graph.py`, both backends) and merges it with its own; an old Host, `--disable_hostlink` or a Slave not yet connected uses its own graph
2. `ResourceTreeSet` + `Registry` → `initialize_device.initialize_device_from_dict()` → `ROS2DeviceNode` instances
3. Device nodes communicate via ROS2 topics/actions or HostLink
4. Backend control notices use `client/host/legacy_adaptor/websocket.py`; complete state and commands use the microbackend HTTP APIs in `server/api/`

### Test Data

Example device graphs and experiment configs are in `unilabos/test/experiments/` (not `tests/`). Registry test fixtures in `unilabos/test/registry/`.

## Code Conventions

- Code comments and log messages in simplified Chinese
- Python 3.14 only (CPython cp314, not free-threaded), type hints expected
- Pydantic models for data validation (`resource_tracker.py`)
- Singleton pattern via `@singleton` decorator (`utils/decorator.py`)
- Dynamic class loading via `utils/import_manager.py` — device classes resolved at runtime from registry YAML paths
- CLI argument dashes auto-converted to underscores for consistency
