# 公共字段、分类与正式入库

读取时机：新增资产、补 CAD/模型/行为后发布修订、批量导入、更新设备或耗材广场条目。仅建模/预览不等于正式入库。

## 定位权威

在目标工作区查找 `config/asset-library/catalog-policy.json`，按其中路径读取已确认的分类索引、确认记录和统一条目合同。该配置是规则与位置声明，不意味着现有发布脚本已自动执行全部检查。没有这份工作区配置时，向目标库查明对应索引，使用本文的 UniLab 公共字段约定；不要硬编码作者的盘符、服务器或分类总数。

当前资产的业务权威是 `统一目录/条目/<uuid>.json`；`统一目录/library.json` 是可重建的检索投影。库根 `library.json` 管理工程包与固定版本，二者用途不同。分类索引是字典与来源映射，不是资产条目清单。原始表格、网页、厂家目录、旧库字段保留为来源，不在每次请求时重新覆盖已整理条目。

## 公共字段：沿用 13 个顶层键

正式条目必须包含下表全部键。完善表示查证并填入实际内容；不适用或查证后未知的可空字段填 `null` 并在入库回执说明，不能为填满表格编造值。损坏 JSON 的原文保存在来源档案，列出待修复项。不得在统一业务层另外加入 `reuse_kind`、`asset_refs`、`driver_id`、`has_cad` 等平行字段。

| 字段 | 入库要求 |
|---|---|
| `uuid` | 稳定且唯一；复用已有业务/资产身份。修订、改名、补 CAD、改分类均不创建第二条身份。 |
| `name` | 非空稳定条目名或原注册名；历史注册身份保留。新设计按中文命名约定，型号不冒充采购 SKU。 |
| `display_name` | 非空展示名，可含型号/图纸号，与实际对象一致。 |
| `resource_type` | 仅 `component / mechanism / device / resource / workcell / tool`。按实际对象边界判断。 |
| `tags` | 字符串列表。新入库必须选定同一 resource_type 下有证据支持的规范分类 ID；场景/用途分面另存为标签。既有条目的旧标签先经映射核对，保留原值证据。 |
| `manufacturer_id` | 引用目标库 manufacturers.json 的稳定 ID，网页从字典显示名称。原数字 ID 按来源限定，名称别名须有证据；同名之外不做模糊公司归并。确实未知可空，冲突旧 ID 保留待核对映射，不根据型号猜厂家。 |
| `description` | 简洁说明对象是什么、用途和关键变体；新入库应补充实质内容，不只复制名称或“暂无”。 |
| `cover` | 工程资产尽量生成当前版本的预览；有值时必须可解析并对应当前包。仅登记产品且无图片时可空并记录缺口。 |
| `device_params` | 沿用对象，保存能查证的型号/料号、尺寸、单位、规格及适用参数；不同孔/配置的差别不能丢失。确无参数为 `{}`，工程假设注明来源。 |
| `model` | 模型/资产关联在这里。工程资产必须有可解析、锁定版本的 `model.targets`，保留 `asset_id`、`package_digest`、`package_path` 和入口等实际合同。仅产品登记允许无工程目标，不能据此宣称模型已入库。原有子字段完整保留。 |
| `module` | 有真实可导入驱动/模块时填写现有约定值；纯模型资产可空。行为文件路径不自动等于 OS 模块。 |
| `source_registry` | 有真实来源注册定义则原样保留，否则可空。它不是可随意覆盖的分类回执容器。 |
| `relations` | 列表；无关联为 `[]`。每项必填 `target_uuid`、`type`，可选 `note`；类型限 `related`、`accessory_for`、`compatible_with`。目标必须是存在的统一条目 UUID；拒绝自关联、同类型重复边和悬空目标。 |

字段核对结果、缺失原因、来源文件/URL、分类选择理由与本次索引摘要放在现有入库回执/来源档案中；保持公共条目仍是 13 键。

## 分类选择

1. 读取当前已确认的 `category-index.json`：`canonical_nodes` 决定分类 ID、父级、路径和资源类型；`source_crosswalk` 提供来源映射。核对确认记录对应的文件摘要，区分已批准树与尚未执行的合并候选。
2. 先确认对象边界和 `resource_type`，再查来源映射及同类型候选。选择证据支持的最具体类别；只有宽泛用途证据时停在有效父类，并写明精度，不推断更细的叶类。
3. 新条目在现有 `tags` 中引用规范分类 ID，名称与路径从分类字典生成，不再加一个顶层 `category_id`。如当前广场适配器只认旧名称标签，必须接通 ID→名称/路径投影或使用经过验证的显式映射后再称“已入库可检索”；仅写入 ID 再被降级成“待归类”不算完成。
4. 无合适分类或来源相互冲突时，先保留 staging 候选和具体缺口。类别扩展沿用工作区审核流程，现有授权覆盖的已确认映射直接使用，不重复索要确认。不能用任意“其他”标签或技术状态标签掩盖未分类。
5. 重定位保留原分类 ID；同义合并记录旧 ID→保留 ID；目录拆分记录旧 ID→多个目标及各来源的实际目标。`navigation_only` 只服务旧链接，不能当作自动赋类的等价关系；不能任选拆分后的首项。

UniLab 已确认的分类原则：

- 设备以 Lab_Scraper 更新分类表为主，仪器信息网补充；半导体与器件制备目录合并。表格中有编码不代表完整国标原文已核验。此前排除的“现有目录”来源不重新导回；设备名含“其他/其它/零部件”的已删除类别按现有映射处理。
- 零部件/模组主要参考嘉立创、怡合达；VC、RoboDK 只按实际对象和证据补充，应用、运动学、产品系列和场景标签不自动作为主分类。
- 保持设备、耗材与工件、零部件等类型边界；同名跨类型不自动合并。成品商业设备与可复用机构的拆分边界仍按本技能的边界参考执行。
- 耗材采用已确认的容器、移液、载架、盖与密封等分支，不恢复“实验器具与通用耗材”旧中间层。Trash 为“耗材与工件 → 实验容器与载体 → 废弃物容器”；废液桶、垃圾袋保留区别。
- Opentrons 原 `displayCategory/category` 与 PLR 类/工厂定义作为来源保留；位点、孔腔、跟踪器不是独立耗材。适配器、校准工具、模块盖按已确认映射处理；源码 category 冲突不得覆盖已核对的映射。
- 材质、孔数、容量、品牌、兼容性、是否带内容物是属性/关系；建模 `family`、文件格式、`sim-ready`/验收状态不是主分类。

## 入库完成条件

先按原有流程查重、封包和验证，再核对公共条目与分类：

1. 13 键齐全，非空字段有效，可空项有实际核查结论；分类 ID 存在、类型一致、原始来源可追溯。
2. 工程包闭包和摘要通过，`model.targets` 与包索引一致；补表示走同一资产修订，分类移动只改元数据，不搬动已发布包。
3. 写入或更新同一条目后执行当前 `unified.py reindex` 或等效工具，读回条目摘要、旧 ID 别名和固定模型引用。`migrate` 是初始化/显式迁移工具，不用它覆盖日常人工维护。
4. 实际验证广场/接口能按新分类、厂家、场景检索到该条目；确认消费者没有把规范分类降级为“待归类”。索引缺少新包记录时完成显式同步，不能只发布到旧工程索引。
5. 保存公共字段检查、分类目标及索引摘要、查重结果、包验证、索引重建和检索读回回执。缺一项时明确“候选/待补全/待同步”，而不是“正式入库完成”。

本次请求仅更新规则或技能时，不批量重写存量条目、不发布 OSS；实际入库按用户已授权范围执行。核查失败时记录原因并完成不依赖该问题的工作。

## 文件树与存储维护

- 保持现有 `<物理分区>/<厂家>/<中文名>__<修订>/` 包目录；细分类树属于索引，分类改名/合并不触发 CAD/USD 文件搬迁。
- 包内继续使用实际的原生 manifest、BOM、`simready_usd/unilab.json`、`readiness.json` 与模型/CAD/行为入口，不另建一份平行 `asset.json`。
- 核心库可在服务器或现有 OSS 前缀；本地可完整缓存。持久化相对对象 key 和摘要，临时签名 URL 只在访问时生成。
- 包文件、BOM 与条目先写入 staging 并验证，再更新索引；同步 OSS 时最后发布索引，读回验证。旧项目使用固定摘要，选择性升级；不以“latest”悄悄替换。
- 分类总表从维护源生成，业务索引从条目生成，工程包索引从已封包内容及发布记录维护。发布副本只读，分别保留回退版本；不手改生成索引作为唯一修复。

## 关联、接口与坐标

`relations` 属于业务条目：没有三维模型的设备也能关联配件和耗材。`accessory_for` 方向为配件→主设备；`compatible_with` 只表达已核对的兼容条件，有限制时写入 note。反向查询从索引生成，关系类型不自动反转。原文件 related 只能导入 related，不提升为兼容、默认配件或装配事实。源名称先唯一解析到业务 UUID，自关联/重复/缺失/歧义均记录处置；完整原关系和依据保存在来源映射档案。

接口放在包内既有 `interfaces_data`：唯一接口 ID、来源接口类型、所属 link、局部位姿、安装/承载角色、兼容条件与证据。宏须展开且接口身份唯一；socket 名称本身不证明兼容。实际组成、数量、实例与位姿仍在 assembly / assembly_data / BOM，不新增公共 parent_id/children。

坐标和转换仍在包内既有元数据：源/目标单位与轴向、变换、工具/版本、输入摘要、几何验证结果。保留 CAD 对应、运动学、碰撞和质量声明。zup 目录名不能代替坐标验证；修改已封包内容发布同资产新修订。仅公共目录回填不重新封包或宣称接口已补完。

## 字典接通与回填

分类发布快照及来源映射位于统一目录的分类子目录，厂家字典用 manufacturers.json，场景等分面用 facets.json；原 tags.json 和 sources.jsonl 作为历史档案保留。新增标签先登记到对应字典。规范分类 ID 与分面 ID 存入 tags；名称、父级路径、厂家显示值及反向关联由 reindex 生成。检查 reindex 实际使用当前字典。

批量迁移先在独立候选目录验证，保留输入快照、每条旧/新值及摘要、原来源和所有映射。不能可靠分类的存量条目允许保留 unresolved 并可筛选，不能把它们宣称为新入库合格条目。语义准入另外检查资料、模型固定引用及用途资格；结构校验和分类可检索并不替代这些证据。

## 机械臂与末端工具

此类条目的品牌定义、型号选择、反向业务 UUID 和迁移验收按 [机器人模块关联](robot-modules.md)。纯几何模型不得仅凭型号名填入未核验的驱动；OS module 只填写实际可实例化的 Device 类，纯资产留空。
