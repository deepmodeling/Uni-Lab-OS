# 源资料路线与工具发现

读取时机：接入新工站、判断转换路线、缺少转换工具或发现源资料不完整时。
本文件指导实际处理；只执行本次交付需要的路线。

## 先确定源资料与目标

1. 列出用户给出的主文件及依赖，记录文件类型、大小、哈希和原始名称。
2. 判断用户要的是浏览、独立资产、可编辑总装、机构运动还是接触任务。
3. 冻结输入身份；新增衍生文件，不覆盖原 CAD、网格或历史回执。
4. 文件很大时优先只读清单或文件系统快照，避免无意义地复制整个目录。
5. 将交付目录与源目录分开，记录每个衍生物的上游输入和转换参数。

| 当前资料 | 首选处理路线 | 本轮能建立的依据 |
| --- | --- | --- |
| SolidWorks 总装及零件 | 原生采集装配与配合信息，再导出交换格式 | 原生组件、配置、变换及可读取的配合 |
| STEP 总装 | 装配审计 → CAD 内核转换 → 独立核验 | 产品树、实例、B-Rep、源变换 |
| URDF/Xacro 与 mesh | 展开模型 → 依赖审计 → 运动与几何对应 | 链接、关节、限位、mesh 引用 |
| GLB/glTF、OBJ、STL、USD | 网格、层次、材质和单位审计 → 分包 | 文件实际保留的几何与结构 |
| 照片、视频、尺寸表 | 视觉参考或测量建模，并标记推定项 | 可见外形与有依据的尺寸 |

多源资料并存时，保留各自身份，建立对应表。不要把较新的文件自动视作权威版本。
先选 1 个有代表性的子总成验证路线，再处理大总装。

### 采购、数据库与照片的证据边界

先清点原 CAD 是否已有目标组件及其配置，再决定重建。把采购 SKU、厂家型号、软件模板名、机械臂物料名、资产 ID 分列；每个尺寸/材质/映射记录来源页码或图中区域、摘要、单位和确认状态。颜色、同容量、同外形只能支持候选，不能单独证明同款；用户选用某资产也不等于确认 OEM 身份。字段与关系检查见 [p0-checks.md](p0-checks.md)。

照片带钢尺时记录标尺与待测特征所在平面、透视校正方法和误差。俯视轮廓可用于平面尺寸，但不直接把同一像素比例用于离开标尺平面的高度；高度需侧视、投影约束或独立尺寸锚点。精确小数不能消除测量不确定性。

参数化家族先分类拓扑，再参数化尺寸：连续透明薄壁不是开孔；缺角需说明仅边缘倒角还是贯穿高度；高/矮插板的侧壁、定位肩和底部结构分别取证，不能只缩放。有效孔容量由内腔到指定液位的体积计算，注明液位、溢流/工作容量、闭合性和误差，不能用外形体积或商品标称值反证几何准确。

## 在当前环境发现工具

先检查随技能的 [通用工具](portable-tools.md)，通过 `scripts/asset_tools.py list` 和对应 `--help` 选择路线；其代码不依赖来源仓。下面的发现步骤用于第三方运行时、商业软件及尚未覆盖的适配器。

自带 `preflight.py --input <file-or-directory>` 可清点路径与环境，并给出 `routes` 路线摘要。STEP/STP 会读取短头部检查 `ISO-10303-21;`：缺少签名则失败；有签名只表示头部可识别，不代表装配、B-Rep 或文件正文有效。工具缺失与源文件错误分别记录；扫描仍会完成其他输入的清点。

- 先读任务目录约定，检查现有应用、运行时、依赖清单和可用连接器。
- macOS/Linux 可用 `command -v`，Windows PowerShell 可用 `Get-Command` 或 `where.exe`，查找 Python、`blender`、`FreeCADCmd`、`usdcat`、`xacro`。
- 命令名和大小写随平台变化；若未找到，再检查已安装应用路径和用户提供的环境。
- Python 用目标解释器的 `importlib.util.find_spec` 探测 `pxr`、`OCP`、`trimesh` 等模块。
- 需要确认实际可用性时，在隔离进程中导入相关模块；记录解释器、模块版本和错误。
- 不在用户现有环境中混装 CAD、OpenUSD 与仿真依赖；可以使用已存在的不同运行时。
- 先检查 CLI 的 `--help`、应用 API 或官方文档，再选实际可执行的接口。
- 只有工具存在且小样本转换成功，才把该路线记录为本环境可用。
- 未提供的商业软件、许可证、远端服务和私有转换脚本都不作为前提。

## SolidWorks 路线

1. 确认主总装、引用零件、配置、抑制状态、轻化状态及外部引用是否完整。
2. 优先从实际打开的原生装配读取组件路径、变换、显示状态和可取得的配合。
3. 保存源配置与采集时间；同一零件在不同配置下可能具有不同几何。
4. 将导出前后组件数、装配范围和代表性部件位置纳入核验。
5. 若导出 STEP，记录导出选项、单位、装配层次和外观信息的保留情况。
6. 配合信息只作为机构候选依据，还要核实作用组件、轴线与自由度。
7. 无原生应用时，继续处理已给出的 STEP/网格和文档，并列出待补的原生信息。
8. 记录 GLB 的实际轴向再转换：文件按 glTF 规范写 Y-up，但 SolidWorks 的几何内容往往是 CAD 的
   Z-up（脚轮共面于同一 Z）。Blender 等导入器会无条件做 Y-up→Z-up，直接导入会把整站放倒；
   导入后在根节点叠加 `Rx(-90°)` 抵消，再以 `export_yup=False` 导出 USD。用脚轮共面性、
   三色灯/上罩的最高 Z 验证，不能只改元数据。

不要用改文件后缀的方法转换 SLDASM/SLDPRT，也不要假设交换格式保留了原生配合。

## STEP 路线

1. 读取头部、协议、单位声明、产品定义、装配关系与顶层实例清单。
2. 分别统计产品、装配边、展开实例和叶节点，保留重复子装配的完整祖先路径。
3. 必须修复名字时创建只改命名字段的衍生 STEP，并验证其他内容未变。
4. 编码修复先作用于元数据；保留原始字节和名称到显示名称的映射。
5. 用可用 CAD 内核导入并网格化，记录容差、角度设置、内核版本和峰值资源。
6. 独立提取或读取源装配变换，和转换结果按完整实例路径比较。
7. 检查全部叶节点：无 mesh 不等于空占位；先判别它是否为实体、壳或面模型。
8. 缺面时先做局部诊断，再按 [identity-assembly.md](identity-assembly.md) 的修复规则处理。

STEP 的构造点极值不是装配包围盒；装配包围盒应由变换后的实际几何计算。
STEP 中没有外观记录时，可添加展示材质，但说明其用途和假设来源。

## URDF / Xacro 路线

1. 收集入口文件、宏参数、include、package 路径和 mesh；保存展开后的 URDF。
2. 审计链接树、关节类型、origin、axis、limit、mimic、碰撞和惯量字段。
3. 解析每个 mesh 的 scale、单位及局部变换，检查引用是否可在交付包内解析。
4. 同时有 CAD 时建立 link ↔ CAD 实例映射，不能仅按近似名称自动认定对应。
5. 关节轴、零位和几何附着通过多个姿态核验，详见 [mechanisms-contact.md](mechanisms-contact.md)。
6. 缺失驱动、传动或控制接口时仍可交付有依据的运动模型，明确支持的操作方式。

厂家 URDF 与现场 CAD 可能来自不同版本；工具法兰、夹爪和传感器需要分别匹配。

## 已有网格或 USD 路线

- GLB/glTF：检查 node/mesh/primitive、实例变换、UV、材质与纹理依赖。
- OBJ：同时收集 MTL 和纹理；不要把 material group 自动当作机械部件。
- STL：它通常不提供可靠的单位、装配或材质；用尺寸和来源建立单位证据。
- USD：检查 stage 单位、up-axis、引用、payload、variant 和实际 composed 结构。
- 按真实装配或操作单元拆分；仅连通分量不能保证是独立零件。
- 缺源 CAD 时保留网格能证明的结构，不补造 B-Rep、配合或厂家身份。
- 无可靠尺寸的照片建模先交付 visual 资产，后续用实测标定推进几何资格。

## 工具缺失与资源受限

继续完成可独立进行的源清单、哈希、依赖整理、格式头检查、命名与映射草案。
输出待转换对象、建议工具及参数、需要补齐的输入和精确续跑入口。
若只能完成准备，应写“已准备，转换未执行”，不要生成外观像完成的空资产包。
长任务先设本轮时间、内存和输出预算；超限时保存日志与已完成回执，调整小样本。
运行仿真前核对当前设备占用和目标配置；缺少运行时不影响交付静态资产与待验项。
安装、远端计算或付费生成仅在本次授权范围内进行；已有授权不重复征求。
