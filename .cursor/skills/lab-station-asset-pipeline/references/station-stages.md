# 按工站所处阶段选流程：步骤与示例提问

SKILL.md 的阶段表给出判断和顺序；这里展开每个阶段的步骤、先问人的节点，以及可以直接复制的示例提问。
三个阶段共用一条原则：**同一个资产行为类同时服务纯仿真、孪生和真机对照**，估计值写依据并标为非标定，
行为、行程、库位的改动写回资产并发布修订，不在设备包里另写行为表、摆位代码或打补丁。

## 阶段一：刚拿到总装 CAD 和需求文档

判断：有总装 CAD（或照片、URDF）和需求文档，资产库里还没有这个工站的资产，也没有设备包。

1. 读需求文档，列设备清单、工艺流程和每台设备要做的动作；按 [asset-library-os.md](asset-library-os.md#2-标准资产库) 查重，标出库里已有和要新建的。
2. 按 [source-routes.md](source-routes.md)、[up-axis.md](up-axis.md)、[decomposition-boundaries.md](decomposition-boundaries.md)、[identity-assembly.md](identity-assembly.md) 把总装拆成设备资产：分件、定关节和库位（[库位几何](asset-library-os.md#库位几何与尺寸验收)）。
3. 生成三层碰撞几何（[collision-profiles.md](collision-profiles.md)）和前端轻量档（[web-profile.md](web-profile.md)）。
4. 给每类有机构的设备写资产行为类并单独试跑（[asset-behavior-mechanism.md](asset-behavior-mechanism.md)）；耗材的孔位、吸头位从耗材资产生成物料定义。
5. 入库字段与分类按 [catalog-intake.md](catalog-intake.md)，再发布成资产修订。
6. 写工站场景和资产锁，用机构运行时在纯仿真下跑通整站，前端能看到画面（[station-twin-dev-guide.md](station-twin-dev-guide.md) 第 4、9、12 节）。

先问人：正式入库或发布修订、改统一目录条目、推送分支、任何付费外观生成。此阶段不写驱动、不接真机。

示例提问：

```
用 lab-station-asset-pipeline 技能，并按 references/station-twin-dev-guide.md 的流程，为新工站 <工站名> 从零开始接入。
输入：总装 CAD <路径>、需求文档 <路径>。
1. 先读需求文档，列出设备清单、工艺流程和每台设备要做的动作，标出哪些设备在资产库里已经有、哪些要新建。
2. 把总装 CAD 拆成设备资产：分件、定关节和库位、生成三层碰撞几何和 web 轻量档。行程、工具点和时长凡是估出来的，都要写依据并标为非标定。
3. 给每类有机构的设备写资产行为类，用 python -m unilabos.simulation try 单独验收，然后发布成资产修订。
4. 写出工站场景和资产锁，在纯仿真模式下用机构运行时把整站跑通，前端能看到画面。
先不写驱动，不接真机。每完成一步汇报结果和待确认项，发布资产、推送分支之前先问我。
```

## 阶段二：通信接口已接好，还没做数字孪生

判断：设备包里驱动已经是 `@device` / `@action`、能连真机，但没有资产行为类、机构运行时配置或场景资产锁。

1. 逐个驱动动作核对资产和行为类：按同名同参对上（[动作名与现有驱动对齐](asset-behavior-mechanism.md#动作名与现有驱动对齐)、[os-asset-binding.md](os-asset-binding.md)）；实在对不上的老驱动，在 `@action` 上加 `motion=`。
2. 缺资产、缺行程或缺行为类的按本技能补齐并试跑；只有“跑某个协议”的动作写[步骤表](asset-behavior-mechanism.md#协议级动作步骤表)；耗材的[物料定义从耗材资产生成](asset-behavior-mechanism.md#耗材的孔位吸头位从耗材资产生成物料定义)。
3. [发布成资产修订](asset-behavior-mechanism.md#发布成资产修订)，更新场景资产锁并重新拉取。
4. 工站仿真配置里按设备打开机构运行时：先纯仿真（`simulated`），再孪生（驱动照常执行、按行为类推演，`estimated`）（指南第 4 节）。
5. 说明反馈等级（`analytic`、`kinematic`、`physics`）和理由（指南第 5 节）；需要时用 OS 碰撞查询做干涉检查（[collision-profiles.md](collision-profiles.md)）。

先问人：发布资产、改锁、推送分支。不改驱动的通信逻辑。

示例提问：

```
用 lab-station-asset-pipeline 技能，并按 references/station-twin-dev-guide.md，为已经有驱动的工站 <工站名> 补上数字孪生。
现状：设备包 <仓库/分支> 里驱动已经是 @device/@action，能连真机。
1. 先核对每个驱动动作在资产库里有没有对应的资产和行为类。对不上的列出来，按同名同参的规则对上；实在对不上的老驱动，在 @action 上加一行 motion=，不要在设备包里另写行为表或摆位代码。
2. 缺资产或缺行为类的，按技能补齐、试跑验收，再发布成资产修订。耗材的物料定义从耗材资产生成。
3. 把场景资产锁更新到新修订，在工站仿真配置里按设备打开机构运行时：先跑纯仿真（simulated），再跑孪生（驱动照常执行、按行为类推演，标 estimated）。
4. 说明这次用的反馈等级（analytic、kinematic 或 physics）和理由，需要时用 OS 碰撞查询做干涉检查。
不要改驱动的通信逻辑。发布资产、推送分支之前先问我。
```

## 阶段三：已有仿真，要切到真机联调

判断：纯仿真和孪生都已用机构运行时跑通，场景资产锁指向固定修订，下一步是上电联调。

1. 列出所有标为非标定的量（行程、工具点、时长、配合深度），给出上真机前要实测或找厂家确认的清单和每项不准的风险（[asset-behavior-mechanism.md](asset-behavior-mechanism.md#资产要补的信息)）。
2. 模式按指南第 1 节**整站一起切，不按设备混合**：整站切到 `twin`（驱动照常连真机、画面按行为类推演），再**一次只给一台设备下发动作**，先空载，读回结果，与行为类推演对比偏差（指南第 4.4、5.5 节）。孪生不读实时传感器，这里的读回是驱动应答、耗时和失败状态，位置偏差靠现场实测；全部设备通过后再整站切 `real`。
3. 偏差超出容差的，改资产的行程或库位，重新发布修订并更新锁，不在设备包里打补丁。
4. 机械臂和转运先用 OS 碰撞查询离线复核规划器给出的轨迹，再低速试跑；孪生运动流的结论不能当作现场无碰撞的证据（[collision-profiles.md](collision-profiles.md)、[mechanisms-contact.md](mechanisms-contact.md)）；抓取稳定性或力有风险时说明是否需要 `physics` 后端。
5. 用真机录一段回放，与仿真回放并排对比（指南第 8 节）。

先问人：**每台设备上电动作之前**、发布资产、改锁、推送分支。不改驱动的通信逻辑。

示例提问：

```
用 lab-station-asset-pipeline 技能，并按 references/station-twin-dev-guide.md，把工站 <工站名> 从仿真切到真机联调。
现状：纯仿真和孪生都已经用机构运行时跑通了，场景资产锁指向 <修订>。
1. 先列出所有标为非标定的量（行程、工具点、时长、配合深度），给出一份上真机前要实测或找厂家确认的清单，并说明每一项不准会带来什么风险。
2. 整站切到孪生（模式整站一起切，不按设备混合），然后一次只给一台设备下发动作。每台先跑空载动作，读回结果，再和行为类的推演对比偏差。全部通过后再整站切到真机。
3. 偏差超出容差的，更新资产的行程或库位，重新发布修订并更新锁，不要在设备包里打补丁。
4. 机械臂和转运先用 OS 碰撞查询检查轨迹，再低速试跑。夹爪抓得稳不稳、力够不够有风险的，说明要不要上 physics 后端。
5. 最后用真机录一段回放，和仿真回放并排对比。
每台设备上电动作之前都先问我。不要改驱动的通信逻辑，发布资产、推送分支之前先问我。
```
