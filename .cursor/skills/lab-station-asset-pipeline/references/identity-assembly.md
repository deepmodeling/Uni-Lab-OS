# 身份、装配与可编辑资产

读取时机：拆分总装、复用几何、转换坐标、导出独立资产或修复缺失几何时。
目标是让部件可追溯、装配可还原、编辑可保存，并能脱离本机重新打开。

## 拆分边界

首先按 [decomposition-boundaries.md](decomposition-boundaries.md) 区分商业整机、自制自动化装置与耗材。以下几何分组、link/刚体或子树操作不改变该资产边界。

## 身份层次

| 对象 | 含义 | 应保存的信息 |
| --- | --- | --- |
| Source | 输入文件的固定版本 | 文件哈希、格式、配置、单位 |
| Prototype | 可以复用的几何及外观定义 | 几何内容、材质、UV、源映射 |
| Occurrence | 原型在装配中的一次出现 | 完整祖先路径、父节点、局部变换 |
| Assembly | 多个实例组成的装配 | 根、层次、实例引用、全局坐标约定 |
| Fixture | 为具体检查或任务构造的配置 | 选中实例、重定位、支撑与控制方式 |

产品名用于显示，稳定 ID 用于关联；中文显示名和安全文件名分别保存。
重复子装配中的相同局部 ID 需要用完整祖先路径区分。
不要将同名、同 mesh 索引或同包围盒的对象直接合并成同一个资产家族。
新增摆放从原资产定义实例化，分配新实例 ID，并记录来源定义与可选的源实例关系；已有实物从库位转移到任务场景时保留原物料 ID。

## 耗材与重复摆放

拆分单位按能否独立取放、消耗、更换或结算判定。载架、瓶身、可拆瓶盖、吸头、滤芯和板分别建立可复用定义；固定结合且任务中不分离的部件可留在同一总成。几何差异或不同规格按配置/修订区分，重复数量写在装配实例中。

例如满架 48 瓶场景通常引用 1 个载架定义、1 个瓶定义、1 个可拆盖定义，生成 1 个架实例、48 个瓶实例及 48 个盖实例。载架的 48 个孔是库位/frame 定义，不是 48 份载架资产。多只相同载架同样共享定义，各实例独立保存库位占用和物料身份。

拆出耗材后核对原总装中的残留几何：一个实物只出现一次。保留静态预览副本时明确其用途，并在运行场景切换中排除重复视觉、碰撞或刚体。取瓶、开盖、放芯改变的是同一实例的父级/库位状态，不能通过创建新物料替换原身份。

优先用 USD reference/payload 或消费者支持的 linked geometry 共享模型。逐实例位姿、可动轴、刚体状态、材料身份和传感读回放在可编辑的实例层。`instanceable` 是优化选项；需要修改子树的机构或物料先验证 override/解除实例化路径，或仅实例化其静态网格子树，不能因共享几何让多个实物共享一个运行状态。

正式分包、目录格式及 graph/OS 库存映射见 [asset-library-os.md](asset-library-os.md)。

厂商销售包装与运行装配分开：盒、插板、吸头分别记录来源，按该型号实际包装组成引用式总成；补充装/裸插板不因外观习惯自动加外盒。不可独立取放或用户明确排除的内置筛片、滤芯保留为内部几何，不强制建独立库条目。

标准机器和本站改造配置分别建定义，通过模组引用表达差异。库位按 [库位几何与尺寸验收](asset-library-os.md#库位几何与尺寸验收) 定义；设备定义不默认持有示例装载物。不同机械臂复用一款盒装耗材时，仍分别保留各自取枪参数。替换只改变已确认的模型绑定；安装偏移、旋转、父级、库位和动作参数按 [P0 替换合同](p0-checks.md) 逐项保护。

## 几何复用与分包

1. 先建立源实例树和映射，再做去重或性能优化。
2. 去重比较完整 primitive 内容：点、索引、法线、UV、材质和已有面索引映射。
3. 内容相同但存储 accessor ID 不同，可以复用；外观或面语义不同则保留差异。
4. 记录存储几何量和展开实例几何量，避免用前者声称模型丢失或精简的比例。
5. 原型保留局部几何；工站摆放只写在实例或装配层，避免双重应用变换。
6. 独立资产去除工站级摆放后，应保留明确的本体原点与坐标说明。
7. 商业整机的门、抽屉等保留在该设备内部运动模型；自制自动化装置的独立机构按拆分边界分包。可拆耗材无论是否装在整机内都独立建定义。
8. 为提高浏览速度启用实例化时，同时保留用户确实需要的编辑方式。

可采用 `geometry / appearance / semantics / motion / contact / assembly` 分层。
工程中间层可沿用项目布局；正式入库按标准包布局。修改材质、运动或接触属性应有清晰的来源与派生关系。

## 坐标与精度合同

记录源单位、目标单位、源轴向、目标轴向、左右手约定及转换矩阵。
矩阵交换数据写明 row/column 存储和向量乘法约定；保留局部与世界变换。
从源装配链独立获得参照变换，避免仅比较同一个编译器导出的两个结果。
轴向用结构锚点、尺寸或原生定义核验，不能只根据画面看起来是否正立决定。
转换后检查镜像、法线方向、三角形绕序和单位缩放是否一致。
UV 属于纹理坐标；单位缩放不应直接缩放 UV，负尺度变换则需核查纹理与切线结果。
操作 frame 单独命名，例如 base、flange、tcp、grasp、place、opening；不要混用 mesh 原点。
frame 标注来源：原生定义、图纸、测量、几何推导或暂定值。

容差由源精度、网格化参数、目标数值格式和操作需求确定。
例如 float32 变换的舍入可能超过极严的矩阵门限，应查清精度来源后设定容差。
若重评门限，保留原报告与误差数据，另写门限依据和新结论，不覆盖原失败。
不要用拟合的全局修正矩阵掩盖单位、轴向或装配链方向错误。

## 装配一致性检查

- 按完整实例路径核对缺失、重复、未知映射和预期数量。
- 检查局部与世界位姿，选择代表性位置验证变换方向和层级组合。
- 比较点、拓扑、材质绑定与源面映射；简化版本单独给出误差预算。
- 包围盒从实际世界坐标顶点取得；旋转后的局部 bbox 只能是保守近似。
- 核对独立资产重开后不带工站摆放，装配入口再正确恢复源位置。
- 转换包含特殊轴变换时，用带非零旋转和平移的小夹具检查矩阵方向。

## 可编辑性检查

使用独立编辑层或工程副本，选一个有子节点和兄弟分支的实际总成。
对它施加一次非零平移与旋转，核对子件跟随、旁支保持和局部/世界变换。
保存后重新打开，再撤销该编辑并重新打开，验证原装配可恢复。
若用户需要编辑实例内部零件，验证解除实例化或 override 的实际可用路径。
记录编辑入口、选中对象和恢复方式；不要只凭“导出了多个文件”声称可编辑。
核对试验前后的源几何与基础层未被意外改写。

## 缺面与异常几何

1. 首先区分转换遗漏、源面损坏、非实体壳、隐藏部件和真实空节点。
2. 给缺失项绑定源实例、B-Rep face/shell ID 或能复核的局部索引。
3. 检查局部子图、面边界与曲面参数；优先局部重新网格化或更换兼容导入路径。
4. 大总装不必整包重跑；可以抽出有依赖闭包的子图进行诊断和恢复。
5. 恢复物以补充层挂回原实例与原坐标，保留原始输入和转换产物。
6. 校验恢复前后的面覆盖、闭合性、方向、尺度和实际顶点范围。
7. 列出仍遗漏的面和原因；非零遗漏不能写成完整恢复。
8. 无可靠源曲面时，补面属于重建假设，记录其位置和对用途的影响。

不能仅因预览没有明显破洞，就认定恢复正确；也不能为碰撞方便把视觉孔洞填满。
只需浏览时可交付带已知缺口的资产；接触任务需单独判断缺口是否影响作用区。

## 包的独立性与交付

使用相对引用收拢必要纹理、mesh、USD 层和语义文件，保留第三方来源信息。
manifest 记录入口文件、内容哈希、源身份、转换版本和已知限制。
把包复制或解压到一个新目录，重新打开用户实际会使用的每个入口。
检查未解析依赖、绝对引用和包外依赖，并确认默认根、单位与轴向。
若存在预期外部依赖，明确列出且提供解析方式，不把它包装为自包含资产。
展示入口、编辑入口、任务入口可以不同，名称与说明应帮助用户直接选对。
只把实际验证通过的入口设为推荐；失败或历史诊断配置可单独保留。
