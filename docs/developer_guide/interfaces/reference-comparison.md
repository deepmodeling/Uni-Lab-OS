# 与原《设备接入与贡献规范》的对照

参照文档为 [UniLabOS 设备接入与贡献规范、OS 配合模式](https://dptechnology.feishu.cn/docx/YRZtdUKkJo1zu4xgjohcc498neh)，
本次读取版本 revision 562。原文兼有接入说明、阶段性实现和后续规划；本章不修改原文，
只说明哪些理念保留、哪些表述需要随当前 dev 更新。飞书访问权限独立于本仓库。

## 比较基线

前一次对比以 `2176e776`（首次 Jazzy 提交的父提交）为起点、`c235e971`（2026-09-06）为终点；
这样会把首次 Jazzy 迁移本身算入变更。本手册迁移统计从 `99558a5a` 开始，终点延伸至
`862ce87a38222ac2d51739f2f89e5daecd3cd907`（2026-09-14）。范围不同，不能直接比较文件数或接口数量。

原对比中的 OpenAPI 为 158 个操作；当前离线全集为 163 个操作，新增内容及实际合同以
[API 全目录](api-catalog.md) 为准。数量增加本身不证明实现完整，例如 handler 的动态状态码和
未声明具体 DTO 的响应仍需人工审阅。旧报告中的六个 demo 也不能替代当前七个 demo 的验收入口。

## 保留的理念

设备能力优先用声明表达，让类型、默认值和说明复用于界面及工作流；降低驱动接入门槛，
让人工与 AI 编写的代码遵守同一合同；设备包独立分发；在连真机前使用可复现的仿真和测试。
这些目标与本轮设计一致，不需要因底层从单一 ROS 走向多 backend 而放弃。

需要补充的是：自动生成参数表单不替代用户确认，仿真成功不替代真机安全验收，
实验语义的组合不替代单个物理动作的状态和历史记录。

## 两种文档服务不同读者

面向用户的说明应先回答：怎样接入设备、怎样绑定物料并运行、遇到错误怎样处理、在哪看进度和日志。
正文不需要列出全部表名、消息模型和 163 条路由，但要说清边界，不承诺尚未实现的能力。

开发者手册则必须保留准确的 method/path、请求模型、响应信封、状态码、版本与幂等语义，
并给出跨进程失败、Site 歧义、人工替换和日志恢复的处理方式。
两者共享同一个源码基线，不能让简版沿用旧策略、详细版采用新策略。

## 本次对比没有做什么

没有重新下载原文附件、修改原飞书文档或发布新在线文档；没有把历史报告的测试结果当作本次运行结果；
没有合入工作区未提交代码；也没有改动 Legacy 的旧后端兼容实现。
现有实现的已知缺口集中在 [迁移与限制](migration.md)，不在说明文档中替代码补齐。
