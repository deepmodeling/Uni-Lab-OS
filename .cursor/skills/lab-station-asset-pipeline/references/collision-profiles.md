# 碰撞表示生产与 OS 消费

读取时机：构建或简化碰撞体、将碰撞资产用于布局/路径检查、优化大场景加载与查询。仅修改外观时，不强制执行本页全部碰撞验收。

## 选择表示与层级

区分显示几何、规划碰撞表示、动力学接触表示。同一资产可共享来源，但三者分别声明用途和证据。`exact` 指保留来源离散表面，不等于 CAD 曲面的解析精确性；查询引擎的三角表面语义也不自动提供实体包含判定。

- 按真实刚体分组。固定紧固件可并入所属刚体；滑台、门、夹指、可取放物料保留独立运动身份。不要跨独立运动体合并。
- 大型固定结构在刚体和功能组内按空间邻近分块，避免整个工站只有一个巨大包围盒。块大小、网格阈值和误差预算由任务尺度决定，不照搬某个工站的数值。
- 合并还须保留接触许可粒度。将来要单独授权的导向件、接触垫或安装接口保留稳定 shape 身份和源映射；同法兰下的不同附件仍可能互相碰撞。
- 孔、槽、瓶口、夹持带、插入口、薄壁、支撑边缘明确标为关键区域，优先精确保留或使用验证过的保腔分解。名称只帮助发现，不能代替覆盖核验。
- 规划可同时提供 `exact` 和保守 `outer`。外包命中后必须精查，不能直接拒绝路径。普通减面网格未经包含/误差证明，不得冒充保守外包。
- 基本体采用目标查询引擎支持的实体盒、圆柱等；三角盒壳不能代替实体包围体。后端不支持的 primitive 明确失败或生成经验证的表示。
- 保守外包可以封住孔作为粗筛，但需要穿孔或插入的动力学接触不能直接使用这个外包。PhysX/SDF/凸分解的 cooking 和物理用途另行验收。

## 覆盖、帧和实例

逐刚体记录采用的 authored collider、显式用于规划的 CAD/显示几何、排除原因和未支持形状。某处存在 collider 不代表整个资产覆盖完整。缺少 authored collider 时，只有明确选择的几何范围可以生成 planning-only 表示；不能据此授予动力学资格。

光线显示、柔性拖链和内部细节按任务声明是否参与。排除项进入证据和查询范围；柔性物体可选择经验证的包络，静态外形不能替代整个行程的柔性碰撞资格。

几何保存为资产/刚体局部坐标，明确米制、轴向、矩阵约定、根变换和初始刚体帧。核验父节点旋转、资产根变换、CAD 锚点及安装偏移的复合次序，每项只应用一次。用非零旋转和非零平移做往返核验，不能只测单位矩阵。

同一定义通过实例复用；实例具有独立身份和位姿，共享几何/BVH。父设备与子机构的模型同时存在时，明确每个实物的碰撞所有者，避免重复计入。仅显示或由其他表示覆盖的实例必须有明确排除说明。

## 生产与标准封包

复用 Asset_pipeline 当前转换器和原生封包器，通过实际 `--help` 与实现确认入口。算法在工具仓维护，技能通过 [portable-tools.md](portable-tools.md) 携带同源、带摘要的运行副本；不另写一套算法，也不依赖作者机器上的固定绝对路径。

1. 固定来源包、配置、USD/CAD 依赖摘要和关键区域；保留源 occurrence/shape 到碰撞对象的映射。
2. 编译精确归组表示与适用的外包，记录工具版本、参数、近似类型和误差/包含证据。对浮点帧误差明确处理方式，保留修正前后的坐标证据。
3. 核验缺件、重复件、局部/世界帧、孔洞、薄壁和所有支持形状。精确归组应核对源三角形覆盖和坐标；外包验证包含，孔槽另测自由空间与障碍探针。
4. 在原资产 ID 下追加修订，用标准 BOM 封包。显示 USD 不因规划简化被替换；变化涉及显示或物理层时分别说明。
5. 用锁定资产生成 OS graph，在更换实例名与布局的第二项目中消费，核对独立状态与几何复用。发布按用户已授权范围处理。

当前标准库的可用组织为：

```text
<标准类别>/<厂家>/<资产>__rNNN/
  com.nvidia.simready.packaging.json
  .metadata/...
  simready_usd/
    <模型>.usdc
    unilab.json
    readiness.json
    collision/
      source/...       # 若未提供可解析的锁定来源引用，随包携带必要来源
      exact/planning-geometry.json + collision.npz + profile.json
      outer/planning-geometry.json + collision.npz + profile.json
```

沿用 `unilab.json.entrypoints.collision_exact/collision_outer` 和 `collision_profiles`。路径、来源摘要、生产者和用途条件进入标准 BOM/元数据；不要引入另一套资产身份或手写伪摘要。来源可以复用已锁定内容，避免为了目录形式无条件复制全部 CAD。

## 运行职责与接触许可

- Asset_pipeline：离线生产、验证和封包。资产保存局部几何、接口、内部接触使用条件。
- OS simulation：解析既有 graph 和资产锁、实例装配、查询会话、当前状态更新。复用现有 `scene.node_bindings`；查询可直接消费 profile，无须启动显示或物理引擎。
- 通用碰撞内核：OS `unilabos.simulation.collision`（FCL/BVH、pair 筛选、按需精查、最小间隙、任意机构的运动链），不读取库存、不推进时钟。
- 机器人模板：型号、FK/IK、规划器、保存轨迹与采样；碰撞场景和内核从 OS 取，不另建一份。
- 领域设备包：结合当前动作与已验证的资产条件，将局部接触声明绑定为具体实例 pair。跨设备接触、抓取和释放由动作状态决定。

许可必须具体到对象对及适用条件。导向副内部允许接触，不等于整个底座与滑块无条件豁免；安装板和外部障碍继续检查。相同刚体的分块可略过内部查询；独立兄弟附件不自动豁免。静态–静态检查可从运动查询中省略，初始装配/布局变化仍需单独核验。

每次查询绑定场景与当前状态摘要。OS/引擎提供完整位姿和当前携带物身份；物理验证读取引擎实际状态，运动学候选明确标注。查询不会修改库存或产生抓取事实。动作阶段改变时重新给出 pair 许可，避免旧许可延续到下一阶段。

几何/配置变化重建对应几何缓存；位姿变化只更新实例空间信息；抓放只更新当前位姿、携带集合和许可。原生缓存按后端版本/参数区分；成功查询不能只按资产摘要缓存。保持会话串行，查询不启动第二个仿真世界。

## 查询内核：OS `unilabos.simulation.collision`

整站碰撞查询是 OS 的通用能力，在 `unilabos.simulation.collision` 里，与机构种类无关。机器人模板 `unilab-robot-runtime` 的 `fcl_collision`、`refined_collision`、`collision_instance`、`cad_scene` 保留原名称和接口，内部直接调用 OS 的实现；机器人库自己只做逆解和路径搜索。依赖 `python-fcl` 0.7.x，只在用到内核时才导入。

| 组件 | 作用 |
|---|---|
| `profile.CollisionProfile(path, expected_sha256=..., lazy=...)` | 读取 profile 的 `planning-geometry.json` + `collision.npz` 并核对摘要；`lazy=True` 时，几何只在被命中后才解码和构建 |
| `instance.CollisionInstance(profile, instance_id, world_from_asset)` | 给同一资产定义加上实例前缀和实例位姿；几何共享，身份和位姿各自独立 |
| `scene.station_scene(document, {节点: (outer, exact)})` | 从 OS 部署图（毫米、父链、行向量朝向，与场景装配同一口径）装配整站：节点位姿 × `asset_transform` × profile |
| `kernel.SceneChecker` | 第 1 级：刚体包围盒、图元包围盒两级向量化剪枝；然后 FCL 窄相位 |
| `refined.RefinedChecker(outer, exact)` | 三级检查：包围盒 → 保守外包 → 只对外包命中的对按需加载精确几何确认；同一对、同一位姿的精确结果复用 |
| `SceneChecker.clearance()` / `RefinedChecker.clearance()` | 在给定距离内求最小间隙（精确版用精确几何）；只在调用时计算，不进入碰撞检查的热路径 |
| `mechanism.KinematicChain` / `Mechanism` / `Attachment` | 由 URDF（含 mimic）或关节列表构成运动链：关节值 → 连杆与碰撞刚体的世界位姿；携带物随连杆走 |
| `query.CollisionQuery.check_states()` | 对一段轨迹逐点检查：碰撞采样点、首批碰撞对、最小间隙、各级计数和耗时 |
| `query.states_from_motion_feed()` / `densify()` | 从纯仿真或孪生的运动流读出逐点状态；在相邻给定点之间按步长线性细分 |
| `query.receipt()` | 把结论写成 OS 轨迹回执，证据等级 `collision_checked`，状态 clear / collision |

调用合同：

- `check(poses, moving_ids=..., allowed_pairs=..., stop_at_first=True)` 只检查“运动体–场景”和“运动体–运动体”两类对。
  - 每个采样点都要给出全部运动体的刚体位姿；
  - 未知 ID、自对、重复豁免、缺位姿，都直接报错；
  - 运动集合或许可变化时重建对缓存，静态体位姿变化立即生效。
- 位姿更新本身不触发检测，判断只在调用 `check()` 的那一刻、针对那一个状态做出。
- 每个检查器实例的访问要串行化；内核不读库存、不推进时钟、不启动仿真世界。
- outer 与 exact 必须来自同一来源：两者的 `source_geometry_sha256` 不一致就拒绝组合。

## 机构种类与运动来源

内核只认“刚体 + 位姿”。机械臂、导轨滑块、三轴龙门、移液头、门和盖、离心机上料机构、夹爪和携带物，都按同一方式接入：

1. **刚体划分**：每个独立运动的部件是一个刚体，有唯一的碰撞所有者；同一刚体登记给两台机构会被拒绝。
2. **位姿计算**：`Mechanism` 由关节值经运动链算出各刚体的世界位姿。
   - 机械臂用品牌包 URDF；
   - 其他机构用资产里登记的关节（轴向、原点、单位、上下限），世界位姿 = 实例位姿 × 运动链 × 刚体局部帧；
   - `Mechanism.from_initial_poses()` 用 profile 里的 `world_from_body_initial` 和导出时的关节值，反推出连杆 → 刚体偏置；
   - 关节超限直接报错（`joint_out_of_limit`）。
3. **携带物**：`Attachment.grasp()` 在抓取时刻记录相对变换，之后物料随连杆走。携带关系取自当前动作状态，不从几何接近推断。
4. **接触许可**：只授权当前阶段有机械依据的具体对，例如安装面、夹指与被夹物料、导向副内部；阶段变化时重新给出。

关节轨迹的必要性：

- 检查是离散的，两次场景更新之间机构扫过的空间要靠中间状态补上；
- 插值必须在关节空间做（例如 SCARA 的连杆走圆弧，直接插值刚体位姿会得到错误的路径）；
- 执行前要预检尚未发生的动作，只有轨迹能给出。

运动来源不同，结论的标注也不同（`check_states(source=...)`）：

| 运动来源 | 用途 | 结论的性质 |
|---|---|---|
| `planned`：规划器保存的轨迹 | 上线前的离线复核 | 规划候选，经碰撞检查 |
| `simulated`：纯仿真行为表运动流 | 整站在 sim 下跑工作流时，顺带检查所有机构的扫掠 | 模拟运动；行为表的轨迹是显示用插值，结论只对这条插值成立 |
| `estimated`：孪生运动流 | 按真机命令推演的画面检查 | 估计运动；没有读取真机位置，不能作为现场无碰撞的证据 |
| `observed`：真机读回 | 事后复核 | 观测运动；仍然只是离散采样 |

记入 OS 轨迹回执（`unilabos.simulation.motion.TrajectoryReceipt`）时：

- 做过检查的记为 `collision_status=clear|collision`，证据等级为 `collision_checked`；
- 没做检查的保持 `not_checked`，不得当作没有碰撞；
- 回放类结论不得高于 `kinematic_replay`；
- 物理合格（`physical_qualified`）还要求另行完成物理验收。

采样步长：关节按弧度、直线轴按米，分别给出（`densify(max_step={...})`）。固定的角度步长不保证笛卡尔间隙。已保存的轨迹保留原内部点和时间，不自行补出未规划的连接段。

## 性能参考与已知缺口

一个大型工站（628 个对象、6,472 个图元）的实测量级如下。迁到 OS 前后，在同一主机、同一时段、同一批冻结输入、同一容器（4 CPU）上背靠背各跑一次。数字只是该配置的证据，不能当作验收线：

| 指标 | 迁移前（机器人库内核） | 迁移后（OS 内核） |
|---|---:|---:|
| 场景就绪（3 次中位数） | 3.89 s | 3.77 s |
| 全量 411 条、260,929 点：查询总耗时 | 772.4 s | 742.8 s |
| 全量：单点中位数 / P95 | 2.52 / 4.66 ms | 2.47 / 4.34 ms |
| 全量：碰撞采样点 | 24,348 | 24,348（逐条一致） |
| 导轨接触证明 22,410 点 | 80.2 s，0 个碰撞 | 82.1 s，0 个碰撞 |

- 首次精查的单点最慢约 4 s，不能把 P95 写成最坏情况保证。
- 与原始 MoveIt CAD 场景相比，分层表示 + 按需精查把场景就绪从约 204 s 降到约 4 s。
- 与全精确表示对照，漏报和误报都是 0。

收益主要来自四点：

1. 按刚体和空间块归组，避免上万个独立物件，也避免一个巨型包围盒；
2. 只查运动对，并用两级包围盒向量化剪枝；
3. 精确几何按需加载；
4. 同一对物体、同一位姿时复用精确结果。

已知缺口：

- 只做离散采样，没有连续扫掠证明；
- 最小间隙需要显式请求，默认不计算；
- MoveIt 在线规划仍由 MoveIt 自己判碰撞，场景几何经 OS 的 profile 读取器加载，但规划时的检查还没有改用 OS 内核；
- 只有已经生成 profile 的资产能参与检查，其余资产要先按“生产与标准封包”补 profile；
- 纯仿真和孪生的跟随循环里还没有接上逐帧检查，目前是对给定轨迹整段检查；
- 第三方软件（例如 RoboDK）的同场景对标尚未完成。

随包的生成工具自带单元测试，覆盖以下几项：

- 精确分块保留三角面和孔洞；
- 固定身份不被合并；
- 浮点误差写回而不是丢弃；
- 外包盒包住全部源点；
- 物料保持精确；
- 来源摘要不符时失败。

运行方式：

```text
cd <skill>/scripts/toolkit/collision-profiles && python -B -m unittest test_profiles
```

查询内核的测试在 OS 的 `tests/simulation/collision/`。

## 验收与性能证据

根据本次用途分别记录：来源/覆盖、引擎加载、离散路径检查、连续碰撞、接触动力学。路径检查保留已保存内部点和时间，不编造连接段；角度步长不是笛卡尔间隙保证。按任务补充孔槽、薄壁、完全包含、附件互碰、许可撤销、位姿变化与缺失输入等反例。

报告离线编译、场景就绪、首次精查、稳定查询分别耗时，并给出样本数、P95/最大值、硬件、资源配额、文件缓存状态、几何和路径摘要。延迟加载成本计入首次查询，不能从统计中隐藏。优化版与原始/精确表示比较碰撞掩码，列出漏报、误报和原数据本就存在的碰撞。

具体工站的秒数、采样间隔和成功案例只作为该配置的证据；没有同场景测量时，保留第三方软件对标缺口。几何通过不自动授权整站执行或真实硬件动作。
