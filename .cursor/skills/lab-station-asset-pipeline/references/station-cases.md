# 三类工站带来的可复用经验

这些经验来自 SZLab 工站、SO503 环肽工站和 SPE 固相萃取平台的处理复盘。此文件只保留方法，不包含源 CAD、控制地址、私有仓库或作者机器路径。历史成功不构成新输入的验证。

## SZLab：从领域资产进入机构与任务

1. **同一装配的多次捕获可能不同。** 零件的姿态与位置曾因捕获配置或重建状态出现差异。比较 occurrence 的世界矩阵、几何和配置，选定具体来源；总包围盒相同不能代替逐件比较。
2. **材质可以独立于几何加工。** 保留逐面材质和贴图分区，对推断的 PBR 做来源标注。未使用 Meshy 的本地材质方案也可以成为有效交付，不必为了覆盖工具而付费生成。
3. **静态对齐不能确认机构归组。** CAD 夹爪的长板和滑块曾被分入错误运动组。至少检查多个开度和机器人姿态，使固定件、运动件和安装件的归属可观察。
4. **接口读数有不同定义。** 机构行程、接触垫有效间距、槽中心间距、抓持中心和 TCP 分别记录。由实际接触面定义夹持参数。
5. **物料身份要贯穿展示和运行。** 曾发生动态杯来自另一支撑台，而料架展示件没有消失；动态枪头与盒内展示件也未绑定。修复方式是源物料到运行实例的一对一映射和基于位姿的槽位占用。
6. **落座精度与占用不同。** 物件轻微晃动可能不满足精密落座阈值，但仍占用槽位。分别定义 seated 和 occupied。
7. **完整环境有自己的验证。** 局部抓放通过后，整机 CAD 检查仍发现护罩和撤爪干涉。保存实际物理步的连杆矩阵，检查环境距离，允许的支撑接触与障碍相交分别处理。

## SO503 环肽：从大型 STEP 到可操作对象

按锁接入行为的案例（2026-11-21）：当时场景锁已由早期 65 包变成 67 包，不能沿用历史数量。
S100 的已发布行为是单文件 namespace package，exports 使用 `角色: "module:Class"`；旧构建器
只接受带 `__init__.py`、字典形式的设备导出。兼容时原样固化源码，不改封包字节，也不凭角色名生成设备。
37 包有行为脚本，但都是机构/运动实现；构建没有生成新的生产设备。场景 owner 中有仅显示用的类，
只冻结这些类会漏掉真正的设备动作，所以回归还冻结领域包的全部声明与配置。
30 个行为通过审阅转发类、非零位姿、双实例隔离和复位检查；氮吹、ForLab、Fluent、G3、I.DOT、
旋转堆栈与倾斜载架的若干关节缺有限行程，保留 incomplete。缺少显式动作消费绑定也单列未完成，
不把审阅命名空间测试当作原工站动作验收。通用流程见 [OS 资产消费与动作绑定](os-asset-binding.md)。

1. **同名零件和重复装配需要完整路径身份。** 源装配记录被多次实例化时，产品名或单一装配记录 ID 都不唯一。保留祖先路径，单独存储共享原型。
2. **几何复用可以减少存储而保留实例。** 比较完整属性、拓扑、材质和来源面映射。只比较顶点会混淆材质或面身份不同的对象。
3. **空 mesh 节点可能是转换丢失。** 检查源 B-Rep 是否有面；必要时提取实体依赖闭包并局部恢复，保存每个三角形的源面身份。可靠性不足的面保留明确缺口。
4. **修复公差和数值精度要有依据。** 原曲面、拓扑修复和离散化分别记录；处理 float32 导出误差时保留原报告及重评依据。不要通过整体拟合掩盖逆矩阵或单位错误。
5. **孔板凸包可能封住任务所需孔腔。** 使用源 CAD 导出的孔位和底面作为探针参考，并做 SDF 与封孔表示的对照。SDF 的连通组件拆分也应证明几何仍对应来源。
6. **夹距应取实际接触截面。** 孔板底部法兰曾决定整体 bbox 最大宽度，按此宽度夹持失败；改用夹持高度处的 CAD 截面后才获得有效接触。
7. **全站自由刚体配置和物件操作资格分开。** 大批原位物料启用自由动力学后曾落稳失败；后续采用完整静态工站加独立物件操作台。操作台的验证仅属于其配置，原位支撑仍需处理。
8. **CAD 机器人外观不提供关节证据。** 缺少运动学资料时可以先用外部测试夹具验证物件接触，并清楚记录夹具身份。

## SPE 固相萃取：SolidWorks GLB 的轴向陷阱

1. **`upAxis=Z` 不代表内容 Z 向上。** SolidWorks 的 GLB 按 glTF 写 Y-up，几何仍是 CAD 的 Z-up；
   Blender 导入器无条件做基变换，整站被放倒。USD 元数据、USD 包围盒"看起来合理"（方箱机器
   `3.94×2.34×1.95` 与 `3.94×1.95×2.34` 都说得通）都不能证明方向对。
2. **地标是唯一可靠的判据。** 8 个脚轮在原始 glTF 中 `z=−0.66` 共面说明地面是 Z；转换后变成
   `Y=0.66` 共面即被放倒。三色灯必须在最高 Z。逐项写进报告，不要只写"已 Z-up"。
3. **模块高度会一起被压扁。** 放倒后 `耗材堆栈` 只有 0.15 m（应为 0.71 m）、`机械手搬运组件`
   0.48 m（应为 0.74 m）；这类"扁"是坐标错误的副作用，不要当建模缺陷修。
4. **先修正再谈其它。** 轴向错误会让所有拆分、OS graph 与入库坐标一错俱错；发现后应重导全部
   派生资产并重入库，而不是只补一个节点或改 `upAxis`。
5. **门禁要能自动抓到它。** 用 `scripts/verify_up_axis.py --glb <station.glb> --landmark 脚轮
   --top 三色灯`：USD 包围盒与原始 glTF 包围盒呈 Y/Z 互换即判失败。详见
   [up-axis.md](up-axis.md)。

## 如何用这些经验

先定位本次症状：源捕获不一致、遗漏/重复对象、运动组错误、内腔丢失、支撑不稳或退出干涉。选择相关的最小检查与修复，验证后再扩展场景。

CoACD、四面体分解、SDF 或某一引擎版本曾失败，并不意味着它们永远不可用。记录输入规模、拓扑、运行时和失败症状；为新对象选择合适方法。历史脚本中绑定的机器人型号、路径与容差需要重新核对。
# SO503 耗材、适配器与运动补包案例（2026-11）

本节是来源特定案例，不把型号、颜色、库位数或尺寸作为通用模板默认值。

- 绿色 50 µL、蓝色 200 µL 旧 COMBI 插板与黄色 BYAS 家族分别取证。黄色高盒与矮盒独立建结构；照片中黑色吸头不能因同盒而继承透明吸头的货号。BYAS01-50-10、BYAS01-200-09、BYAS01-1000-13 是用户提供的选用 SKU；借亚通/Acumen 尺寸图建模并不确认其 OEM 对应。
- BYAS31-02-06 收集板、BYAS31-03-03 单槽、BYAS31-03-06 十二道槽：俯视照片里透明薄层容易误读为开孔；连续侧壁、底部孔形过渡、全高缺角都需与 CAD/图纸交叉确认。2.2 mL 采用 CAD 反向参数化版本是用户选型；另建共享几何但独立存储的 1.6 mL 定义，不由几何相同推定有效体积相同。
- 逗点 004902-5 保持原厂结构，顶部字标为同材质浅刻；PP 光学参数通过固定壁厚和机位的对比调节，不能把“医疗级 PP”变成已测透射率。筛片/滤芯保留内部表达，按本次用户范围不单独入库。
- 安乾适配器检查内部长短边夹片、转角筋、96 个圆底入孔及支撑高度。禁止靠开槽规避错误夹片位置；顶部适配器与底座分开引用。几何可定版，而底座螺纹/有效深度无依据，紧固仍待确认。加热振荡栏维持一块底板加四个模块。
- Fluent 多配置、G3 公共机器与本站改造、CEM 标准机器与本站四工位分别维护设备定义。设备库位描述允许放置的耗材，装载物归工站实例。耗材 FCA/MCA 复用时不能覆盖各臂取枪参数。
- R191 回归范围为 56 个运动包、296 个关节、99 个随动库位及 43 个总装实例。原始复制中 6 包有 BOM 外的 Python 缓存；新目录按封存 BOM 物化后 56 包闭包与运动检查通过。总装初检有 4 个旧基线引用缺失；按发布前索引摘要恢复只读比较副本后，43/44 项通过（含 graph 不变量），仍发现当前总装的 Fluent 分支引用已删除的 R186 项目路径。保留此失败，不当成全量替换已验证。这是历史回归结果，不是后续版本的永久资格。
